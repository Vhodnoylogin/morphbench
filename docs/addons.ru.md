# Дополнения для браузера

English: [addons.md](addons.md).

Документ описывает API **v1**, включая добавочные возможности обновления и состояния сеанса,
входящие в **Application 0.8.0**. Установите Application с обязательным Runtime, как описано
в [updating.ru.md](updating.ru.md). Дополнение — локальный пакет HTML/JavaScript/CSS,
добавляющий вкладку инспектора в просмотрщик с сервером. Центральный вид модели остаётся
видимым. Самодостаточный HTML, экспортированный через `mb.py web`, не активирует дополнения.

V1 поддерживает только браузерные дополнения. В нём нет импорта Python, нативных плагинов,
серверных обработчиков, установочных скриптов, API редактирования вершин или связи с игрой.
Отдельный мод может поддерживать своё дополнение через публичный интерфейс, не добавляя
свои форматы и расчёты в Morphbench.

## Установка, обновление, включение и отключение

В менеджере дополнений просмотрщика загрузите ZIP, проверьте сведения о пакете и явно включите
его. После установки пакет всегда **отключён**. У включённых совместимых пакетов появляются
свои вкладки инспектора. Выбор вкладки загружает входную страницу; отключение активного пакета
в этом просмотрщике выгружает фрейм и убирает вкладку. Закрытие инспектора дополнения
не отменяет изменения, уже внесённые им в предпросмотр.

Пакеты и состояние включения — локальные данные машины в настроенном `addonDirectory`.
Они не входят в релиз или Git; каталог по умолчанию в рабочей копии исключён через .gitignore.
Пустая настройка означает каталог `addons` рядом с активным файлом конфигурации. Установка
по-прежнему отклоняет существующий ID с `alreadyInstalled`; для замены нужна отдельная
операция **обновления**.
Несовместимый или повреждённый пакет включить нельзя.

Обновления Application сохраняют установленные дополнения и файлы их реестра. Сами пакеты
дополнений они не обновляют; для этого служит отдельная операция ниже. Данные SDK для вкладки
по-прежнему живут в пределах сеанса браузера и не являются долговременным хранилищем проекта.

Для обновления отключите пакет, загрузите заменяющий ZIP через элемент обновления в менеджере,
проверьте результат и явно включите пакет снова. Цель определяется полем `id` манифеста ZIP;
если такой пакет отсутствует, возвращается `notFound`. Обновление включённого пакета возвращает
`updateRequiresDisabled`, в том числе при повреждении его установленных файлов. Успешное
обновление оставляет пакет отключённым. `version` — непрозрачная метка: разбор и сравнение
семантических версий не выполняются, поэтому допустимы та же метка или метка, выглядящая старше.
Ошибка проверки или публикации сохраняет ранее выбранный пакет и состояние включения.

Те же операции доступны без открытия модели:

```text
python mb.py addons --json
python mb.py addons --install <package-folder>/scene-inspector.zip --json
python mb.py addons --enable scene-inspector --json
python mb.py addons --disable scene-inspector --json
python mb.py addons --update <package-folder>/scene-inspector.zip --json
python mb.py addons --enable scene-inspector --json
```

`--install`, `--update`, `--enable` и `--disable` взаимоисключающие; используйте отдельные команды.

Для уже работающего локального сервера:

| Запрос | Тело | Результат |
|---|---|---|
| `GET /api/addons` | — | `{apiVersion:1, addons:[...]}` |
| `POST /api/addons/install` | Байты ZIP, `Content-Type: application/zip` | Запись установленного пакета, изначально отключённого |
| `POST /api/addons/update` | Байты ZIP, `Content-Type: application/zip` | Запись заменяющего пакета, оставшегося отключённым |
| `POST /api/addons/enabled` | JSON `{id:"scene-inspector", enabled:true}` | `{apiVersion:1, addons:[...]}` после изменения |
| `GET /addon-assets/<id>/<generation>/<relative-file>` | — | Проверенный ресурс текущего выбранного и включённого поколения |
| `GET /addons/<id>/<relative-file>` | — | Прежний маршрут к ресурсу текущего включённого пакета |
| `GET /web/addon-sdk.js` | — | Браузерный SDK v1 от хоста |

Запросы включения/отключения требуют `Content-Type: application/json`. Браузерные запросы
управления должны приходить со страницы хоста; запросы с другого источника отклоняются.
Локальные скрипты могут не отправлять `Origin`, как и в [HTTP API](http.ru.md).
При ошибке HTTP возвращает неуспешный статус и `{error:"message"}`; ошибки пакетов
дополнительно содержат `code:"machineCode"`.
Не считайте неуспешный запрос пустым списком.

Обычная запись пакета содержит поля манифеста, непрозрачную строку `generation`,
`enabled` (логическое), `compatible`
(логическое) и `status` (`enabled` или `disabled`). У несовместимых установленных пакетов
`status:"incompatible"`, у недействительных — `status:"invalid"`. Оба случая содержат
диагностику `error:{code,message}`. Проверяйте `enabled` и `compatible` отдельно.
Новая установка и успешное обновление получают новый идентификатор поколения даже при
совпадении меток версии. Передавайте поколения без изменений; не разбирайте и не вычисляйте их.
Корневой просмотрщик привязывает URL ресурсов фрейма и каждый запрос SDK к выбранному поколению.

## Формат пакета и ограничения

В корне ZIP должен находиться `addon.json`, а входной HTML и остальные ресурсы — под тем же
корнем. Не упаковывайте содержащую их папку. Пример манифеста:

```json
{
  "id": "scene-inspector",
  "name": "Scene inspector",
  "version": "1.0.0",
  "apiVersion": 1,
  "entry": "index.html",
  "description": "Neutral example of the Morphbench browser add-on API."
}
```

`id`, `name`, `version`, `apiVersion` и `entry` обязательны; `description` необязателен.
Неизвестные поля манифеста отклоняются. ID соответствует `[a-z][a-z0-9-]{0,63}`.
`name` и `version` — непустые строки; `apiVersion` — целое число `1`. Входная страница
должна указывать на включённый в пакет файл `.html`. Пути относительные, с согласованным
регистром и прямыми косыми чертами. Абсолютные пути, `..`, обратные косые черты, ссылки,
зашифрованные элементы ZIP, повторяющиеся пути и коллизии регистра, зарезервированные
Windows имена отклоняются. Допустимы `.html`, `.css`, `.js`, `.json`, `.svg`, `.png`, `.jpg`, `.jpeg`.

Объект конфигурации `addonLimits` задаёт следующие ограничения по умолчанию:

| Ключ | По умолчанию | Значение |
|---|---:|---|
| `maxArchiveBytes` | 16 MiB | Размер загруженного/сжатого архива |
| `maxFiles` | 256 | Число путей ZIP, включая явные и неявные каталоги |
| `maxFileBytes` | 4 MiB | Несжатый размер одного файла |
| `maxTotalBytes` | 16 MiB | Суммарный несжатый размер |
| `maxCompressionRatio` | 200 | Максимальная степень сжатия одного элемента ZIP |
| `maxManifestBytes` | 64 KiB | Размер манифеста |

Перед публикацией проверяется весь архив. Изменения защищены неблокирующей блокировкой ОС:
другой процесс CLI/сервера получает `busy`, вместо потери обновления состояния включения.
Файлы пакета и состояние включения отделены от исходных моделей и скелетов. При установке
и обновлении код пакета не выполняется.

Формат реестра **v2** выбирает неизменяемые каталоги поколений через одну атомарную замену
указателя `state.json`. Извлечённые файлы и заменяющий файл состояния сбрасываются через
`fsync` перед публикацией/фиксацией. Читатели видят полный старый или новый пакет; проверены
внедрённые ошибки и аварийное завершение процесса до фиксации состояния. Это не доказывает
сохранность при любом отключении питания или сбое файловой системы. Предыдущие поколения
и байты прежних пакетов остаются на диске; автоматической сборки мусора нет. После аварии
может остаться невыбранное поколение. Текущий хост читает прежние реестры v1
и при изменении записывает состояние v2. Старые хосты отклоняют v2; сохранение
прежних байтов пакетов не обеспечивает поддержку такого возврата к старой версии.

Чтобы упаковать нейтральный пример, выполните из `examples/scene-inspector`, указав
выходную папку вне репозитория:

```text
python -m zipfile -c <output-folder>/scene-inspector.zip addon.json index.html main.js style.css
```

Установите ZIP и затем включите `scene-inspector`. Пример умеет обновлять снимок сцены,
открывать модель из каталога, задавать существующий морф, сбрасывать морфы и выбирать
ракурс. Язык подписей берётся у хоста. Внешних зависимостей и запросов за пределы машины нет.

## SDK и протокол сообщений

Загрузите SDK хоста как классический скрипт перед своим скриптом:

```html
<script src="/web/addon-sdk.js" defer></script>
<script src="main.js" defer></script>
```

Используйте отдельные локальные файлы JS и CSS; хост ограничивает скрипты и ресурсы
локальными файлами пакета/SDK и блокирует сетевые соединения. Импорта модулей ядра Morphbench
нет. В частности, CSP `connect-src 'none'` блокирует **все** соединения `fetch`/XHR, включая
относительный запрос JSON, включённого в пакет. Разместите таблицу соответствий в локальном
классическом JS, встроите JSON в HTML для чтения своим скриптом либо предложите пользователю
выбрать файл данных через браузерный File API. XML не входит в допустимые расширения ресурсов.
Публичный глобальный объект содержит три метода:

```javascript
const host = await MorphbenchAddon.connect(); // результат host.info
const scene = await MorphbenchAddon.request("scene.get");
const unsubscribe = MorphbenchAddon.on("scene.changed", ({ method }) => {
  // Отложите объединённое чтение; не записывайте изменения на каждое уведомление.
});
unsubscribe();
```

`connect()` возвращает promise с `host.info` и сохраняет успешное подключение на время жизни
фрейма. `request(method, params={})` возвращает promise с результатом метода.
`on(event, handler)` передаёт обработчику `data` события и возвращает функцию отписки.
У каждого запроса свой тайм-аут **10 секунд**. При завершении, ошибке или тайм-ауте удаляются
ожидающий запрос и его таймер. Отклонённый `Error` имеет машинный код `.code`. Прямое открытие
примера вне фрейма Morphbench завершается `notConnected`.

Транспорт — `window.parent.postMessage(message, "*")`. Звёздочка нужна потому, что фрейм
с ограничениями имеет непрозрачный источник. SDK принимает сообщения только от `window.parent`,
проверяет версию API и сопоставляет уникальный строковый ID ответа с ожидающим запросом.
Хост независимо проверяет отправивший фрейм и включённый пакет.

```javascript
// Запрос
{ type: "morphbench-addon:request", apiVersion: 1, id: "unique-id",
  method: "scene.geometry", params: { shape: "Body" } }
// Успешный ответ
{ type: "morphbench-addon:response", apiVersion: 1, id: "unique-id", result: {} }
// Ошибка
{ type: "morphbench-addon:response", apiVersion: 1, id: "unique-id",
  error: { code: "unknownShape", message: "..." } }
// Уведомление
{ type: "morphbench-addon:event", apiVersion: 1,
  event: "scene.changed", data: { method: "..." } }
```

`scene.changed` сообщает об операции предпросмотра хоста. Строка `method` обозначает
операцию для диагностики; это не рецепт воспроизведения. В уведомлении нет ID запроса.
Чтения не меняют сцену. Объединяйте частые уведомления в отложенное чтение и отделяйте
чтения от изменений, чтобы не создать обратную связь. Смена модели заменяет страницу
и фрейм: после загрузки подключитесь снова и прочитайте состояние.

## API v1

Принимаются только перечисленные ниже параметры. `params` должен быть объектом, в том числе
для чтения. Неизвестные параметры, неверные числовые типы, неконечные числа и недействительные
пакеты изменений отклоняются до изменения предпросмотра. Нулевое значение морфа удаляет
имя из карты ненулевых значений.

| Метод | Параметры | Результат |
|---|---|---|
| `host.info` | `{}` | `{apiVersion:1, addon:{id,name,version}, capabilities:[methodName,...], language:"en"\|"ru", scope:"browser-session", stateScope:"tab-session", stateLimits:{maxBytes,maxDepth}}` |
| `state.get` | `{}` | `{value:null\|JSON}`; `null`, если значение ещё не сохранено |
| `state.set` | `{value:JSON}` | `{value:JSON}`; проверенная независимая копия сохранённого значения |
| `state.reset` | `{}` | `{value:null}` после удаления сохранённого значения дополнения |
| `models.list` | `{}` | `{root:string\|null, entries:[catalogEntry,...]}`; включает модели без TRI |
| `models.open` | `{name:catalogRelativeName}` | `{navigating:true}`, затем текущий просмотрщик перезагружается |
| `morphs.get` | `{}` | `{names:[string,...], values:{name:nonzeroNumber,...}}` |
| `morphs.set` | `{values:{name:finiteNumber,...}}` | Форма `morphs.get` после слияния всего пакета изменений |
| `morphs.reset` | `{}` | Форма `morphs.get` со значением `values:{}` |
| `scene.get` | `{}` | Снимок сцены, описанный ниже |
| `scene.geometry` | `{shape:existingShapeName}` | Снимок геометрии, описанный ниже |
| `view.get` | `{}` | `{state:viewState, presets:{presetName:[yaw,pitch],...}}` |
| `view.set` | Необязательные `{preset,yaw,pitch,zoom,pan,visibleShapes}` | Форма `view.get` после проверенных изменений |

`capabilities` перечисляет поддерживаемые подключённым хостом методы, включая `state.get`,
`state.set` и `state.reset` в этом расширении. Перед вызовом добавочного метода у старого
хоста v1 проверяйте capabilities. Запись каталога содержит
`name`, `nif`, `tri` (может быть null), `kind` (может быть null), `folder`, `file`, `index`.
Передавайте в `models.open` точное `name` из `models.list`; произвольные пути файловой системы
не принимаются. Ответ отправляется до перехода. Выбор модели сохраняет активное дополнение
и использует полный каталог (`all=1`). Он сбрасывает несохранённые изменения морфов, камеры
и рабочей области точно так же, как обычный выбор модели. Перед переключением сохраните
работу обычными средствами хоста.

Имя морфа должно уже существовать в `names`; v1 не создаёт морфы. `morphs.set` объединяет
значения, сохраняя остальные ползунки. При любом неверном имени или значении не применяется
весь пакет. Если морфы не загружены, `morphs.get` возвращает пустые имена и значения.

`view.set` принимает существующее имя ракурса; конечные `yaw` и `pitch` в градусах;
положительный конечный `zoom`; `pan:[x,y]` из двух конечных чисел, представимых как float32; `visibleShapes:[name,...]`
из существующих имён частей. `visibleShapes` заменяет выбор частей просмотрщика, а `[]`
скрывает их все. Политика видимости исходного файла остаётся отдельным состоянием. Сначала
применяется ракурс, затем явно заданные углы заменяют его углы; пропущенный угол сохраняет
текущее значение или значение ракурса. Действуют обычные ограничения и нормализация камеры:
проверяйте возвращённое состояние. Сначала проверяется весь запрос.

`state` в результате `view.get` содержит точные числовые значения камеры: `yaw`, `pitch`, `preset` (может быть null),
`zoom`, `pan`, `colouring`, `highlightMorph`, `visible` (null означает выбор всех),
`respectFileVisibility`, `showFileHidden`, `colliders`, `bumper`, `width`, `height`, `light`
и необязательный `focus` (null при отсутствии). В `light` находятся `follow`, `direction`,
`cameraDirection`, `worldDirection`, `ambient`, `diffuse`, `fill`; в фокусе — `name`, `centre`,
`radius`. Числа состояния камеры не округляются для вывода. V1 позволяет задавать только
перечисленные выше параметры камеры.

`scene.get` возвращает:

```javascript
{
  open: true,
  names: { nif: "body.nif", tri: "body.tri", skeleton: "skeleton.nif", ragdoll: null },
  summary: { /* обычная сводка Morphbench */ },
  shapes: [{ name: "Body", vertices: 100, triangles: 160, visible: true }],
  workspace: { mode: "morphs", tab: "sliders", tabs: [/* доступные вкладки */] },
  colliders: { /* снимок редактора капсул */ },
  fileVisibility: { /* признаки файла и отдельное включение просмотрщика/политики */ }
}
```

Имена файлов — имена без каталогов либо null; сводка может содержать пути исходников.
`summary` содержит `nif`, `tri`, `triKind`, `shapes`, `vertices`, `bones`, `morphs`, `skeleton`,
`colliders`, `ragdoll` и `bounds:{min,max}`. Она описывает открытые источники, а не наблюдение
игры. `visible` части сообщает о её включении при текущем выборе просмотрщика и политике
видимости файла. Без модели допустимы `open:false`, `summary:null`, `shapes:[]`.

`workspace` описывает текущий режим/вкладку. `colliders` — данные редактора капсул: доступность,
геометрия в локальном пространстве тела, выбранная капсула, признаки поддержки/редактируемости,
правки/исходные капсулы и отдельные `bodyMatrices`/`nodeMatrices`, если они доступны.
Это снимок для чтения; в v1 нет метода записи капсул. Семантика пространств описана
в [workspace.ru.md](workspace.ru.md), признаки исходного файла в `fileVisibility` —
в [visibility.ru.md](visibility.ru.md). Снимки не разрешают игровые переопределения и не
симулируют физику.

`scene.geometry` возвращает:

```javascript
{
  name: "Body", space: "model",
  vertices: [/* x0,y0,z0,x1,y1,z1,... после текущих морфов */],
  baseVertices: [/* x0,y0,z0,... в покое */],
  triangles: [/* i0,i1,i2,... индексы вершин с нуля */],
  boneNames: [/* имена используемых частью костей */]
}
```

Массивы — отдельные копии. Их изменение меняет только копию дополнения. Позиции находятся
в пространстве модели, в игровых единицах, без преобразования камеры. У капсул другое,
явно локальное пространство тела; не сравнивайте их концы напрямую с вершинами модели.
Для преобразования используйте соответствующие матрицы снимка. Точность геометрии соответствует
данным браузерного просмотрщика: дельты морфов квантованы в int16. Побитовое совпадение
с исходными расчётами с плавающей точкой или игровым скиннингом не обещается.

Коды ошибок хоста включают `invalidParams`, `unknownMethod`, `serverRequired`, `noMesh`,
`unknownShape`, `incompatibleApi` и `staleGeneration`. Ошибки данных сеанса описаны ниже.
Ошибки реестра/отключённого пакета могут иметь другие коды.
Ошибки транспорта SDK: `timeout`, `notConnected`, `disconnected`, `invalidResponse`.
Выводите сообщения через `textContent`, без вставки в HTML.

## Данные сеанса дополнения

Страница хоста хранит одно значение JSON на ID дополнения в собственном `sessionStorage`;
непрозрачный фрейм не получает объект хранилища. Хост определяет пространство имён по
проверенному отправляющему фрейму и установленному ID. Параметры не позволяют выбрать
пространство другого дополнения; лишние ключи, например `id`, отклоняются. Если значения
ещё нет, `state.get` возвращает `{value:null}`.

```javascript
const host = await MorphbenchAddon.connect();
if (["state.get", "state.set", "state.reset"].every(name => host.capabilities.includes(name))) {
  const { value } = await MorphbenchAddon.request("state.get");
  // Восстановите свои элементы управления явно; применение морфов требует отдельного запроса.
  await MorphbenchAddon.request("state.set", { value: { selectedFamily: "example" } });
  await MorphbenchAddon.request("state.reset");
}
```

Значения — независимые копии конечных ациклических данных JSON: null, логические значения,
строки, конечные числа, массивы и простые объекты со строковыми ключами. Dates, Maps, нативные
объекты, `undefined`, неконечные числа и циклы отклоняются с `invalidState`; повреждённый JSON
в хранилище также возвращает `invalidState`. По умолчанию `addonStateMaxBytes` равен **65536**
байтам сериализованного браузером JSON в UTF-8, а `addonStateMaxDepth` — **32**; `host.info.stateLimits`
публикует их как `maxBytes` и `maxDepth`. Корневое значение имеет глубину 0, каждое вложенное
значение увеличивает её на один. Превышение размера или глубины возвращает `limitExceeded`.
Недоступность хранилища или превышение браузерной квоты возвращает `stateUnavailable`.
Отклонённая запись сохраняет прежнее значение. Результаты чтения/записи являются копиями.

Данные сохраняются при `models.open`, перезагрузке и пересоздании фрейма в той же вкладке
и на том же источнике браузера, а также при обновлении пакета с тем же ID. Сохранение,
чтение и сброс данных не применяют и не воспроизводят изменения предпросмотра, не создают
`scene.changed` и не сбрасывают морфы. Дополнение само решает, когда восстановить свои
элементы управления и запрашивать ли отдельные явные изменения сцены.

Гарантия заканчивается при закрытии вкладки, изменении источника или очистке хранилища
браузера; источник включает порт, а сервер не обещает постоянство порта. Браузер может
восстановить прежний сеанс вкладки, но это не долговременное хранилище проекта. Экспортируйте
важную работу через явный файловый процесс.

## Изоляция и жизненный цикл

Инспектор работает в iframe с `sandbox="allow-scripts"`, без `allow-same-origin`.
Он не имеет доступа к DOM хоста и не импортирует его внутренние объекты. Поддерживаемый
публичный интерфейс — SDK и версионированный протокол выше; внутренние классы просмотрщика,
структура DOM и буферы отрисовки не являются API дополнений. V1 не предоставляет учётные
данные, произвольный доступ к файловой системе или выполнение на сервере.

Это разделение доверия, **не среда безопасного запуска вредоносного кода**. Включённый пакет
выполняет JavaScript, может запрашивать разрешённые изменения предпросмотра и читать доступные
метаданные исходников/геометрию. Устанавливайте пакеты, исходникам которых доверяете. CSP
блокирует внешнюю сеть, возможности переходов iframe ограничены, но защиты от уязвимостей
браузера, исчерпания ресурсов или вредоносных вычислений не обещается.

Отключение выгружает активный фрейм в том просмотрщике, где выполнено действие. Каждый
последующий запрос SDK проверяется по текущему состоянию включения/совместимости реестра
и поколению фрейма. После замены и повторного включения старый фрейм не может действовать
от имени нового пакета: следующий запрос SDK получает `staleGeneration`, и хост закрывает
фрейм. Отложенный переход также повторно проверяет поколение. URL ресурсов старого поколения
возвращают `staleGeneration`; прежний маршрут ресурсов обращается к текущему пакету и не
фиксирует его идентичность. Перезагрузите просмотрщики, оставшиеся открытыми при обновлении,
чтобы загрузить текущую корневую страницу хоста и фрейм пакета.
Отключение не откатывает завершённые правки и не гарантирует мгновенную остановку JavaScript
в другом открытом просмотрщике; закройте/перезагрузите такие окна, чтобы завершить их фреймы.
Пересоздание фрейма сбрасывает собственное состояние дополнения в памяти; явно сохранённые
данные сеанса остаются в пределах описанного срока жизни. Правки браузерного
предпросмотра автоматически не становятся состоянием сервера, диска или игры. Результат
дополнения не доказывает игровые контакты, физику, отсечение или визуальное качество в Skyrim.

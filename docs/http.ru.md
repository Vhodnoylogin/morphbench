# Автоматизация через HTTP

English: [http.md](http.md).

Работающий сервер Morphbench поддерживает локальные HTTP-запросы. Этот же сервер используют
окно запуска и просмотрщик в браузере. Для повторяемых операций сервера используйте запросы;
интерфейс нужен для проверки изображения или действия, которого нет в API.

## Запуск и среда

Из корня репозитория:

```text
python mb.py serve --no-browser --root <папка-мешей>
```

Чтобы читать собранную Data профиля MO2, запускайте окно или Python через MO2. Сервер,
запущенный вне MO2, не получает виртуальную Data от HTTP-клиента. Перед открытием мешей
проверяйте `insideMo2` и `dataRoot` в `/api/environment`. Окно можно запускать документированной
операцией `/run` локального моста MO2, указывая зарегистрированное имя программы.
Мост относится к отдельному проекту и имеет собственную авторизацию и проверку занятости.

`serve` может подключиться к существующему серверу. Закройте прежний экземпляр перед
запуском новой версии: процесс на том же порту не обязательно относится к новому комплекту.

## Доступные маршруты

Следующая таблица использует GET. По умолчанию адрес — `http://127.0.0.1:8767`; адрес
и порт задаются настройками. Исходный код и подробности протокола — в `presenters/serve.py`.

| Маршрут | Результат |
|---|---|
| `/api/environment` | Среда и текущий корень; `insideMo2` сообщает о виртуальной Data сервера |
| `/api/catalog?all=0&rescan=0` | Меши с морфами; `all=1` включает записи без TRI, `rescan=1` обновляет список |
| `/api/payload?index=0` | Открыть запись каталога по номеру и вернуть данные просмотрщика |
| `/api/payload?name=<относительный-путь>` | Открыть запись по имени из каталога; путь кодируется для URL |
| `/api/payload` | Вернуть данные текущего открытого меша |
| `/api/root` | Текущий корень и число мешей |
| `/api/root?root=<папка>` | Задать корень обзора; под MO2 он должен оставаться внутри Data игры |
| `/api/workspace` | Текущий режим, редактор капсул, физический документ, номинальные пределы и текст экспорта конфигурации |
| `/api/shutdown` | Остановить сервер после отправки ответа |

Запросы каталога и данных меша также принимают `root=<папка>`. Чтобы открыть меш без TRI,
передавайте `all=1` и в запрос каталога, и в запрос данных, например
`/api/payload?name=femalebody_1.nif&all=1`.
Запрос данных без открытого
меша возвращает ошибку. Открытие меша меняет выбор сервера; установка корня и остановка
также являются действиями, хотя маршруты используют GET.

## Запросы рабочего пространства

Эти маршруты POST требуют JSON в UTF-8 и `Content-Type: application/json`. Запросы браузера
с другого адреса отвергаются; локальные скрипты могут не указывать `Origin`. Размер входа,
число числовых полей и число действий воспроизведения ограничены настройками рабочего пространства.

| Маршрут | Тело JSON | Результат |
|---|---|---|
| `/api/physics/import` | `{"kind":"fsmp","text":"<system/>"}`; для TXT используйте `cbpc` | `{"document":...}`; только разбор, без изменения состояния сервера |
| `/api/workspace` | `{"actions":[{"method":"workspace_mode","args":["physics"]}]}` | Применить ограниченный пакет действий и вернуть состояние рабочего пространства |
| `/api/workspace/skeleton` | Рецепт `morphbench-workspace` версии 1, включая `source` и `actions` | Байты нового NIF скелета как `application/octet-stream` |

Состояние содержит `workspace`, `colliders`, `physics`, `envelopes` и `text`.
Также возвращается `fileVisibility`: статические сведения файла и отдельный результат выбора
просмотрщика/политики. В пакетах разрешён `respect_file_visibility(on,show_hidden=false)`.
Неполная цепочка родителей не даёт подтверждённого состояния; см. [видимость](visibility.ru.md).
`text` — текущий экспорт конфигурации с сохранением исходного текста либо `null` до импорта.
Разбор не устанавливает документ: воспроизведите `physics_replace` с возвращённым документом,
затем `physics_set` с идентификатором импортированного поля и конечным числом. Сохранённое
физическое состояние содержит исходный нормализованный `document` и словарь `edits` для воспроизведения.

Разрешены методы `workspace_mode`, `workspace_tab`, `physics_replace`, `physics_set`,
`collider_select`, `collider_set`, `collider_translate`, `collider_add`, `collider_remove` и
`collider_reset`. У каждого действия ровно два поля: `method` и массив `args`. Отвергнутый
пакет сохраняет прежнее редактируемое состояние. Имена режимов — `morphs`, `colliders`,
`physics` и `slots`; [руководство рабочего пространства](workspace.ru.md) описывает вкладки,
системы координат и примеры рецептов.

Скачивание скелета проверяет путь/хеш исходного скелета и его текущие байты, затем воспроизводит
рецепт на копии. Маршрут возвращает байты и не принимает произвольный путь записи в файловой
системе. Сохраняйте результат в новый файл. Неподдерживаемые формы остаются доступными только для чтения.

Для PPB тот же маршрут разбора принимает `{"kind":"ppb","text":"..."}`. Установите документ
через `ppb_replace`, правьте существующие поля через `ppb_set(fieldId,value)`. Явно выберите
обе записи для `ppb_to_collider(capsuleId,bone,index)` или
`ppb_from_collider(capsuleId,bone,index)`. Эти методы также разрешены в пакетах действий.
`ppb_link(capsuleId,bone,index)` включает явную двустороннюю правку исходника,
`ppb_unlink()` завершает её, сохраняя правки. Поле `binding` отдельного состояния PPB равно
null или `{capsule,bone,index}`. При связи `ppb_set`, `collider_set` и `collider_translate`
согласованно меняют геометрию и числовые фрагменты исходника. Связывание копирует исходную
геометрию в рабочую капсулу и не определяет соответствие PPB в игре. Ошибка сохраняет оба состояния.
`GET /api/workspace` возвращает отдельное состояние `ppb` и `ppbText` (null до импорта).
Импорт PPB не меняет скелет и независимый документ FSMP/CBPC. Правка текста работает без меша.
Для переноса капсул нужен загруженный скелет; рецепт привязан к его пути и хешу.
См. [границы поддержки PPB](ppb.ru.md): изменения во время игры не воспроизводятся.

## Пример

```python
import json
from urllib.parse import urlencode
from urllib.request import ProxyHandler, build_opener

base = "http://127.0.0.1:8767"
client = build_opener(ProxyHandler({}))

def get(route):
    with client.open(base + route, timeout=60) as response:
        return json.load(response)

environment = get("/api/environment")
entries = get("/api/catalog")
payload = get("/api/payload?" + urlencode({"name": entries[0]["name"]}))
print(environment["insideMo2"], payload["summary"])
```

Импорт конфигурации и её установка в состояние сервера с теми же `client` и `base`:

```python
from pathlib import Path
from urllib.request import Request

def post(route, body):
    request = Request(base + route, method="POST",
                      data=json.dumps(body, ensure_ascii=False).encode("utf-8"),
                      headers={"Content-Type": "application/json"})
    with client.open(request, timeout=60) as response:
        return json.load(response)

parsed = post("/api/physics/import", {
    "kind": "fsmp", "text": Path("physics.xml").read_bytes().decode("utf-8")})
state = post("/api/workspace", {"actions": [
    {"method": "physics_replace", "args": [parsed["document"]]},
    {"method": "workspace_mode", "args": ["physics"]}]})
print(state["physics"]["fields"], state["text"])
```

Для этих вызовов браузер не требуется. Ошибки JSON содержат поле `error` и возвращаются
с кодом ошибки HTTP. Неудачный запрос нельзя трактовать как успешный пустой результат.

## Область действия

API предоставляет операции каталога, среды, данных просмотрщика и ограниченного рабочего
пространства; произвольные методы `MorphBench` он не открывает. Правки рабочего пространства
в браузере остаются локальными до отправки их рецепта; GET не собирает неотправленные правки.
Изменённые в браузере ползунки морфов не становятся автоматически рецептом расчёта на сервере.
Для воспроизведения по файлам и экспорта в новые пути используйте `mb.py workspace`.

Наложения FSMP — номинальные пределы в исходных системах координат, а не симуляция движения.
Неразрешённые умолчания, наследование и неподдерживаемые правила скрывают предпросмотр.
CBPC возвращает только исходные параметры; его ограничители не равны итоговому смещению
или непосредственным угловым пределам. См. [workspace.ru.md](workspace.ru.md).

Расчёты — в [cli.ru.md](cli.ru.md), упаковка — в [building.ru.md](building.ru.md),
контракты реализации — в [рекомендациях по разработке в репозитории](https://github.com/Vhodnoylogin/morphbench/blob/main/CLAUDE.md).
Эти инструкции не входят в архив выпуска.

## Локальные пакеты дополнений (разработка)

API v1 в `feature/addons` включает следующие добавочные маршруты в разработке:

| Запрос | Тело | Результат |
|---|---|---|
| `GET /api/addons` | — | `{apiVersion:1, addons:[...]}`; записи содержат непрозрачную `generation` |
| `POST /api/addons/install` | Байты ZIP, `Content-Type: application/zip` | Установленная запись, отключена; существующий ID возвращает `alreadyInstalled` |
| `POST /api/addons/update` | Байты ZIP, `Content-Type: application/zip` | Заменяющая запись, отключена; `id` манифеста выбирает существующий отключённый пакет |
| `POST /api/addons/enabled` | JSON `{id,enabled}`, `Content-Type: application/json` | Обновлённый список с обёрткой |
| `GET /addon-assets/<id>/<generation>/<relative-file>` | — | Ресурс текущего включённого поколения; старый идентификатор возвращает `staleGeneration` |
| `GET /addons/<id>/<relative-file>` | — | Прежний маршрут к текущему включённому пакету |

Обновление возвращает `notFound` при отсутствии ID манифеста и `updateRequiresDisabled`
для включённого пакета. Метки версий непрозрачны и не сравниваются. Установка/обновление
применяют настроенные лимиты ZIP, проверяют пакет до публикации и возвращают ошибки пакета
как `{error,code}` с неуспешным статусом HTTP. Успешное обновление создаёт новое поколение,
но требует явного повторного включения. Реестр v2 использует неизменяемые поколения и один
атомарный указатель состояния; прежние байты остаются без автоматической сборки мусора.
Новые исполняемые файлы читают прежние реестры v1; старые отклоняют v2. Ограничения при аварии
описаны в [контракте реестра и жизненного цикла](addons.ru.md).

Корневой просмотрщик привязывает фреймы и каждый запрос SDK к поколению. Повторное включение
замены не разрешает работу старого фрейма: следующий запрос получает `staleGeneration`,
после чего фрейм закрывается. Перезагрузите просмотрщики, оставшиеся открытыми при обновлении.
Изолированная вкладка использует [публичный браузерный SDK](addons.ru.md) для предпросмотра
и `state.get`/`state.set`/`state.reset`; методы состояния являются сообщениями SDK, а не
маршрутами HTTP. Значение в принадлежащем хосту `sessionStorage` ограничено ID дополнения
и вкладкой/источником браузера и сохраняется при выборе модели/перезагрузке. Оно отделено
от состояния сцены, не воспроизводится автоматически и не является долговременным
хранилищем проекта.

Запросы к корневой странице и API с другого источника или из iframe отклоняются, включая
действия GET. Локальные CLI-клиенты могут не передавать `Origin`. CSP пакета `connect-src 'none'`
блокирует все fetch/XHR, включая JSON из пакета: используйте данные в локальном классическом JS,
встроенный в HTML JSON или выбранные пользователем файлы через File API. XML-ресурсы пакета
не разрешены. В существующем архиве 0.8.0 этой инфраструктуры нет.

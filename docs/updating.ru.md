# Установка и обновление morphbench

English version of this page — [updating.md](updating.md).

Раздельный выпуск состоит из двух пакетов. Один раз установите совместимую пару, затем
обновляйте Application, сохраняя требуемый ею Runtime. Пакеты скачивают вручную;
автоматической загрузки в morphbench нет.

| Пакет | Что поставляет | Как определяется |
|---|---|---|
| Runtime | `morphbench.exe`, встроенный `python/`, `vendor/`, исходники пересборки лаунчера и сведения о сторонних компонентах | `runtime-manifest.json`: версия/идентификатор Runtime, точные SHA-256 файлов и `contentHash` |
| Application | Python-код верстака, файлы браузера, переводы, документация и `update.py` | `application-manifest.json`: версия Application, принадлежащие ей файлы и требуемые идентификатор/хеш Runtime |

Версии Runtime и Application независимы: Application `0.8.0` может требовать
`runtime-1-win64`. Хеш требуемого содержимого тоже должен точно совпадать. Более новый
Runtime или Runtime с той же версией Python не становится заменой автоматически. Оба
манифеста остаются в корне установки и показывают установленные версии. При запуске выпуска
они и файлы Runtime проверяются до импорта нативных зависимостей.

## Первая установка

1. Скачайте ZIP Application и точный ZIP Runtime, указанный в требованиях её выпуска,
   например `morphbench-application-0.8.0.zip` и `morphbench-runtime-1-win64.zip`.
2. Создайте новую папку установки вне игры и папок модов.
3. Распакуйте в неё **содержимое** внешней папки Runtime. Распакуйте **содержимое** внешней
   папки Application в **ту же папку**. Имена внешних папок различаются; не оставляйте
   пакеты в двух соседних папках и не вкладывайте один в другой.
4. Убедитесь, что `morphbench.exe`, `mb.py`, `update.py`, `runtime-manifest.json`,
   `application-manifest.json`, `python/` и `vendor/` лежат рядом.
5. Запустите `morphbench.exe`. Отдельно ставить Python или Blender не требуется. Для MO2
   добавьте exe этой установки, как описано в [quickstart.ru.md](quickstart.ru.md).

Лаунчер и его пути не изменены. Запись MO2 с `python/python.exe` и аргументами `mb.py serve`
тоже работает; укажите эту же папку установки в **Start in**.

## Обновление Application

Скачайте новый ZIP Application самостоятельно. Храните ZIP вне папки установки.
Сохраните работу, остановите сервер кнопкой **Остановить** в лаунчере и закройте лаунчер.
Можно вместо этого выполнить из папки установки в PowerShell:

```powershell
.\python\python.exe .\mb.py serve --stop
```

Следующие команды тоже предназначены для PowerShell; замените `<install>` и
`<application.zip>` настоящими путями. Сначала проверьте пакет и установленные файлы:

```powershell
& "<install>\python\python.exe" "<install>\update.py" --check --package "<application.zip>" --json
```

`--check` выводит данные проверки в JSON, не применяя обновление. Может создаваться или
использоваться только блокировка установки. Проверьте сообщённые версию Application,
требуемый Runtime и результат проверки. Затем примените тот же ZIP:

```powershell
& "<install>\python\python.exe" "<install>\update.py" --package "<application.zip>" --json
```

Цель по умолчанию — папка, в которой находится `update.py`, независимо от текущего
рабочего каталога. Используйте `--target "<install>"`, только когда явно обновляете другую
раздельную установку. Дождитесь успешного завершения перед повторным запуском morphbench.

Обновлятор проверяет точное требование Runtime, список файлов пакета и установленные файлы
Application. Он отказывает, если байты существующего файла Application отличаются от её
установленного манифеста. Храните собственные правки исходников отдельно; не подменяйте
манифест ради обхода проверки. Работающая Application удерживает совместную блокировку
установки, обновлятору нужна исключительная. Если блокировка занята, остановите процесс,
который использует установку, и повторите попытку. Параллельный запуск обновляторов отклоняется.

## Что сохраняется

Обновление Application заменяет принадлежащие ей по манифесту файлы и удаляет устаревшие
файлы, только если они принадлежали предыдущему манифесту Application. Оно сохраняет:

- `morphbench.json` и `morphbench.launcher.json`;
- установленные дополнения вместе с файлами их поколений, состояния и сеансов;
- произвольный `addonDirectory` и прочие неизвестные пользовательские файлы;
- файлы Runtime и существующий двоичный файл лаунчера.

Обновлятор не объявляет неизвестные файлы частью Application. Принадлежность задают
манифесты. Пакет не может через обновление Application заменить Runtime или состояние пользователя.

## Восстановление прерванного обновления

Обновления используют резервные копии и журнал восстановления. Отдельные принадлежащие
Application файлы заменяются по очереди; атомарной замены всей папки установки нет.
Если обновление прервалось до фиксации, оставьте Application остановленной и запустите
восстановление установленным обновлятором:

```powershell
& "<install>\python\python.exe" "<install>\update.py" --recover --json
```

Восстановление возвращает записанное состояние Application до обновления из резервных копий
транзакции. Сохраняйте журнал восстановления и резервные файлы до завершения обновлятора.
Прочитайте его результат JSON; запускайте программу только после успешного восстановления,
затем проверьте и повторите нужное обновление. Если восстановление сообщает о конфликте
или отсутствующей копии, сохраните установку и отчёт для диагностики.

## Переход со старого полного архива

Старая установка одним архивом не имеет манифеста принадлежности файлов Application.
Обновлятор не угадывает, какие её файлы относятся к выпуску, и не преобразует её автоматически.

1. Остановите старый сервер и сохраните старую папку нетронутой.
2. Установите совместимые Runtime и Application в **новую папку**, как описано выше.
3. Скопируйте собственные `morphbench.json`, `morphbench.launcher.json` и установленные
   дополнения в новую папку. Сохраняйте вместе файлы поколений, состояния и сеансов
   каталога дополнений. Если используется произвольный `addonDirectory`, явно сохраните
   или измените этот путь в настройках.
4. Перенаправьте запись MO2 на новую установку и проверьте настройки перед продолжением.

Переносите собственное состояние, не накладывая старые программные файлы на новую установку.
Рабочие копии исходников без манифестов выпуска по-прежнему пригодны для разработки;
этот обновлятор предназначен для раздельных установок с манифестами.

## Изменения Runtime и пределы проверки

Обновление Application не может обновить Python, нативные зависимости или лаунчер.
Изменение Runtime, включая исправление безопасности зависимости, требует отдельно
проверенного выпуска Runtime и манифеста Application, который на него ссылается.
Следуйте инструкции установки такого выпуска.

Хеши определяют, какие байты установлены и требуются. Они не являются подписями, одобрением
антивируса или модерации Nexus. Python и JavaScript остаются исполняемым кодом даже в пакете
Application без нативных двоичных файлов. Используйте пакеты из источника, которому доверяете.

Создание обоих пакетов и прежнего полного архива описано в [building.ru.md](building.ru.md).

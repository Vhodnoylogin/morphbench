# Видимость файла и выбор для просмотра

English version — [visibility.md](visibility.md).

Morphbench хранит локальный флаг `NiAVHidden` выбранного NIF и сведения о родителях отдельно
от галочек частей в просмотрщике. По умолчанию показываются все выбранные части, включая
скрытые в файле и части с неполными сведениями. Это позволяет изучать скрытую геометрию,
не утверждая, что движок её рисует.

**Учитывать видимость NIF** оставляет только части с полной подтверждённой видимостью файла.
**Показать также скрытые в файле части** дополнительно включает подтверждённо скрытые части.
Неопределённые части при включённой политике остаются исключены; для их изучения отключите
политику. Галочки частей, **только** и **показать все** независимо задают выбор просмотрщика:
они не меняют флаги NIF, не отключают политику и не снимают исключение неопределённых частей.

Это статические сведения файла. Инструмент не проверяет отсечение в движке, контроллеры
видимости, выбор модели первого лица, перекрытие камерой, VRIK или положение шлема.
Переключатели не меняют исходный NIF и файлы установленных модов.

## Публичный фасад Python

```python
from morphbench import MorphBench

bench = MorphBench()
bench.open('body.nif', tri='', skeleton='')
report = bench.file_visibility()
bench.respect_file_visibility(True)
confirmed_visible_shapes = bench.visible_shapes()
bench.respect_file_visibility(True, show_hidden=True)
known_shapes_including_hidden = bench.visible_shapes()
bench.hide('some-shape')  # отдельный выбор просмотрщика; флаги NIF остаются прежними
bench.show_all()          # только выбор частей; политика файла продолжает действовать
bench.respect_file_visibility(False)
```

`file_visibility()` возвращает копию обычных данных:

| Поле | Значение |
|---|---|
| `source`, `scope`, `runtimeEvaluated` | Путь выбранного NIF, `nif-file` и всегда false |
| `respectFileVisibility`, `showFileHidden` | Два переключателя политики просмотра |
| `complete` | Модель открыта и состояние файла определено для каждой части |
| `counts` | Число состояний `visible`, `hidden`, `unknown`; отдельно `viewerVisible` и итоговое `inspectionVisible` |
| `shapes` | Сведения каждой части и текущий результат выбора |

В каждой части есть `name`, номер блока `block`, полное целое `localFlags`, локальный флаг
`localHidden` либо null, список `ancestors` с номерами/именами/флагами родителей,
`ancestryComplete`, `complete`, `inheritedHidden`, `effectiveHidden`, состояние `state`
(`visible`, `hidden`, `unknown`) и машинные коды `issues`. Проверяется только младший бит
`NiAVObject.flags` с числовым значением1; остальные биты сохраняются. Имена узлов не служат
идентификаторами графа.

`localHidden` может быть известен при неполной цепочке родителей. `inheritedHidden=true`
может отражать найденного скрытого родителя, даже если другой участок цепочки не определён.
Это не делает итог подтверждённым: при неполном графе или недоступных флагах возвращаются
`effectiveHidden=null`, `state=unknown`, `complete=false`. Узел без найденного родителя не
считается корнем автоматически. Чтение использует явный корень и полные списки дочерних
блоков PyNifly. Повторы ссылок, несколько путей, циклы, потерянные родители и ошибки чтения
не позволяют подтвердить итог. Ошибка необязательных сведений видимости не мешает открыть
читаемую геометрию. У созданных в памяти частей сведения файла изначально неизвестны.

Отдельно возвращаются `viewerVisible`, `inspectionVisible` и `exclusion`: сначала
`viewer-hidden`, затем `file-unknown`, затем `file-hidden`, либо null для включённой части.
Это решения просмотрщика, а не новые флаги файла. `view_state()` содержит два переключателя;
рецепт сохраняет их, а ошибочный пакет действий не меняет прежнее состояние.

Отрисовка, кадрирование и вычисления, берущие вход через `visible_shapes()`, учитывают эту
политику, включая обычную оценку покрытия и подгонку капсул. Полные отчёты частей, морфов и
границ сохраняют свой описанный охват. Явный список `skin_points(shapes=...)` остаётся явным
выбором вызывающей стороны и не переписывается фильтром просмотрщика.

## CLI и HTTP

```text
python mb.py visibility body.nif --json
python mb.py visibility body.nif --respect-file-visibility --json
python mb.py visibility body.nif --show-file-hidden --json
python mb.py render body.nif --respect-file-visibility --out NEW-visible.png
python mb.py render body.nif --show-file-hidden --out NEW-known-shapes.png
```

Без `--json` команда `visibility` печатает таблицу локальных, унаследованных и итоговых
сведений, их полноты и включения в просмотр. Параметры доступны командам, принимающим меш.
`--show-file-hidden` включает политику файла: подтверждённо скрытые части показываются,
неопределённые остаются исключены. Команда отрисовки из интерфейса воспроизводит изображение.
Запомненный `showFileHidden` при отключённой политике не влияет на картинку; рецепт хранит
оба точных логических значения.

`GET /api/payload` и `GET /api/workspace` содержат `fileVisibility`. Политика задаётся через
существующий ограниченный маршрут `POST /api/workspace`:

```json
{"actions":[{"method":"respect_file_visibility","args":[true,false]}]}
```

Новые маршруты и произвольный вызов методов не добавлены. `visibilityGraphLimit` ограничивает
выделение памяти для графа, обход и объём сведений о родителях. При достижении ограничения
возвращается неизвестное состояние, геометрия и флаги не меняются. Для использования исходных
точек входа пересборка EXE не требуется.

# `launcher\` — точка входа для Mod Organizer 2

English version of this file — [README.md](README.md).

MO2 подменяет файловую систему только процессам, которые запустил сам: моды сводятся
в один игровой `Data` библиотекой usvfs. Чтобы увидеть меши всей сборки, верстак должна
запустить **сама** MO2, а она запускает исполняемые файлы, а не скрипты. `morphbench.exe` —
как раз такой файл: небольшое окно с состоянием сервера, корнем обзора и кнопками поднять,
остановить и открыть страницу. Запущенное из MO2, оно поднимает `python mb.py serve` своим
потомком, и тот видит сведённый `Data`.

Application **0.8.5** использует отдельный **Morphbench Launcher v1** (`runtime-1-win64`);
их версии независимы. Оба ZIP выпуска начинаются с `root/Morphbench/`. В объединённой
установке `launcher/` содержит прежний EXE и нативный Runtime, `app/` — Application,
а `plugins/` — установленные аддоны. Запускайте `Morphbench/launcher/morphbench.exe`.
Обёртка архива `root/` поддерживает необязательный MO2 Root Builder; при ручной установке
из неё извлекают `Morphbench`. См. [установку и перенос](../docs/install-layout.ru.md).

| Файл | Что это |
|---|---|
| `morphbench.cs` | окно на C# — целиком |
| `mb.py` | Python-диспетчер новых выпусков, который находит и запускает Application |
| `morphbench.manifest` | осведомлённость о DPI и общие элементы управления, вкомпилированные внутрь |
| `build.cmd` | собирает `..\morphbench.exe` штатным компилятором .NET Framework; ASCII и CRLF — намеренно |
| `make-icon.py` | рисует `morphbench.ico`; `morphbench.png` — его предпросмотр и продукт сборки |

Собирается один раз: `launcher\build.cmd`. Результат ложится в корень репозитория рядом
с его `mb.py` и в git не попадает — это продукт. Сборка исходников сохраняет прежнюю плоскую структуру; упаковка
выпуска помещает существующий EXE в `Morphbench/launcher` без перекомпиляции. Исключение —
`morphbench.ico`: он версионируется через Git LFS,
потому что эти байты едут внутри exe и без них рецепт его не пересоберёт.

## Может зависеть от

**HTTP-API сервера и командной строки.** Всё, что делает кнопка, делает и командная строка:
`serve --status`, `serve`, `serve --stop`, `/api/root`, открыть страницу. Больше отсюда
до верстака ничего не достаётся — окно такой же клиент, как и все.

Прежний EXE находит `mb.py` рядом с собой, в явно заданной папке или через
`MORPHBENCH_HOME`. В новой структуре это `launcher/mb.py` — диспетчер из обоих пакетов.
Он выбирает Application по явному абсолютному `MORPHBENCH_APP`, соседней `../app`
или единственной полной установке в корне игры. Неоднозначные кандидаты отклоняются.
При запуске Application проверяет требуемый идентификатор Runtime, хеши файлов и точный
встроенный `launcher/python/python.exe`; переопределение Python должно указывать на него же.

Исходники и прежние плоские установки сохраняют свои пути. В исходниках без манифестов
выпуска Python ищется через `MORPHBENCH_PYTHON`, ключ `python` в `morphbench.json`,
папку `python\` рядом с `mb.py`, `python.exe` в PATH (кроме заглушки Windows Store),
реестр `PythonCore` и `py.exe`. Плоская раздельная установка с манифестами по-прежнему
проверяет закреплённый Runtime. Пути конкретного компьютера в окно не вкомпилированы.

## Кто не вправе его импортировать

Никто и не может: это отдельная программа на другом языке. Зависимость идёт в одну сторону —
окно зовёт верстак, а верстак об окне не слышал.

## Правило, которое решает, что здесь лежит

**Окно ничего не считает и ничего не знает про меши.** Разбор доводов и оконный обиход —
и только. Кнопка, умеющая то, чего не умеет `mb.py`, — та же поломка, что и управление
на странице, до которого не дотянуться из командной строки.

**Окно — удобство, а не условие.** Запись в MO2, у которой двоичный —
`<Morphbench>\launcher\python\python.exe`, доводы — `mb.py serve`, а **Start in** —
`<Morphbench>\launcher`, делает ту же работу: usvfs внедряется так же, и сервер видит
тот же сведённый `Data`. Для прежней плоской установки укажите её корневой
`python\python.exe`, а в **Start in** — корень этой установки. Кто предпочитает не запускать
неподписанный двоичный, теряет только кнопки, — поэтому ничто и никогда не должно начать
работать только через эту папку.

# Локализация

BodySlide собирает тело, а morphbench его проверяет: читает собранное и говорит, в порядке ли
морфы, сферы охвата, капсулы столкновений и настройки физики — вне игры, за секунды. Эта страница
о словах, которыми он всё это говорит, и о том, как заставить его говорить их на твоём языке.

Написана она для переводчика, а не для программиста. Питона здесь нет. Всё, что программа
печатает — заголовок каждой таблицы, каждый отказ, каждая кнопка в окне, каждая подпись на
странице в браузере и даже текст `--help` в командной строке, — это строка в JSON-файле внутри
`locale\`. Добавить язык значит скопировать файлы и переписать правую часть каждой строки. Код при
этом не трогают, и трогать в нём нечего.

## Три шага

**1. Скопировать английскую папку.** Язык — это папка, названная двухбуквенным кодом языка, так
что немецкий становится `locale\de\`.

```
xcopy /e /i locale\en locale\de
```

**2. Перевести правые части.** Открой каждый файл новой папки в любом редакторе, который сохраняет
в UTF-8. Строка выглядит так:

```
"model.noShape": "the mesh has no shape %(name)r; it has: %(have)s",
```

Слева от двоеточия — ключ. **Его не менять никогда.** Справа — текст. Его меняют целиком, сохраняя
куски вида `%(...)`; про них — правила ниже.

**3. Назвать язык в настройках.** `morphbench.json` лежит рядом с `mb.py` и создаётся при первом
запуске, если его ещё нет. Первая строка в нём — язык:

```
"language": "de",
```

`auto` означает язык Windows, и именно с этим значением программа поставляется. Любое другое
значение — имя папки внутри `locale\`.

Это вся работа. Чтобы попробовать язык, не трогая настройки, — или проверить, на каком языке
заговорит чужая машина, — задай переменную `MORPHBENCH_LANG`: она перевешивает настройку на один
запуск.

```
set MORPHBENCH_LANG=de
```

В PowerShell то же самое пишется как `$env:MORPHBENCH_LANG = "de"`. Переменную читают одинаково
и командная строка, и сервер, и окно.

## Правила, по которым перевод остаётся рабочим

| Правило | Почему |
|---|---|
| Ключ — это метка, и он не меняется | Ключи выглядят как `err.noShape`, а не как английские фразы. Фразу правят при вычитке, и будь она заодно ключом, все переводы разом отвязались бы от кода. Метка правку фразы переживает. |
| `%(name)s` подставляется по имени | Порядок слов — твой. `%(count)d shapes in %(file)s` может стать «в файле %(file)s частей: %(count)d». Кусок переставляется куда угодно внутри фразы, и его можно повторить. |
| Все куски сохранить, новых не добавлять | Проверки сравнивают набор имён `%(...)` в твоём тексте с английским и ругаются на расхождение. При работе имя, которого код не присылает, роняет подстановку целиком: возвращается неподставленный текст, а значения дописываются к нему в скобках, чтобы ничего не потерялось. Некрасиво, но не сломано. |
| Букву после скобки не терять | `%(name)s` — слово, `%(count)d` — целое число, `%(size).1f` — число с одним знаком после точки, `%(name)r` — имя в кавычках, как его показывает Python. Кусок переставляют целиком, а не разбирают на части. |
| Непереведённый ключ откатывается | Ключ, для которого в твоём языке строки нет, берётся из английского. Нет и там — показывается сам ключ: короткий, латиницей и находимый поиском. Ничего не падает, и пустого места не остаётся. |
| Пустое значение равно отсутствующему | `"page.btnOnly": ""` покажет английское слово, а не пустую кнопку. Удалить строку и опустошить её — одно и то же, и так задумано. |
| Один ключ в двух файлах — ошибка раскладки | Внутри одного языка ключ объявляется ровно один раз. Побеждает первый файл, а о столкновении делается запись — вместо того чтобы один текст молча съел другой. |
| Ключ, начинающийся с `#`, — заметка для тебя | В JSON нет комментариев, поэтому заметки живут ключами: `"#": "Таблицы для консоли: заголовки и вердикты."`. Всё, чей ключ начинается с `#`, пропускается и никогда не показывается. У каждого файла может быть свой `#` и сколько угодно заметок вида `#что-нибудь`. |
| Сохранять в UTF-8 | Метку порядка байтов (BOM) оба читателя терпят, так что редактор, который непременно её добавляет, вреда не наносит. |

Две вещи помельче, на которых спотыкаются чаще всего:

**Знак процента сам по себе.** В тексте, где есть куски `%(...)`, отдельный знак процента надо
удваивать: `%(outside)s%% кожи снаружи`. В тексте, где кусков нет вовсе, пиши его как есть —
`99%`, — потому что такой текст отдаётся нетронутым. Это касается строк, которые печатает Python;
в `page.json` и `launcher.json` всегда пишется одиночный `%`.

**Ширина столбца — часть текста.** В `text.json` некоторые строки собирают таблицу руками:

```
"text.fitMissed": "%(bone)-18s points %(points)-6s did not fit",
```

`-18` — это ширина столбца. Твои слова, скорее всего, длиннее английских, так что ширину
приходится увеличивать — и увеличивать одинаково во всех строках этой таблицы, иначе столбцы
перестанут сходиться.

**Счёт предметов.** Каталог подставляет текст, а не склоняет слова. Там, где число меняет
формулировку, в коде стоят два разных ключа: одна капсула и несколько капсул — две отдельные
строки. Русскому и двух форм мало — «1 капсула», «2 капсулы», «5 капсул», — а третьей взять
неоткуда, и правил множественного числа в каталоге нет вовсе. Обходят это перестройкой фразы, где
число стоит отдельно от слова: «капсул: %(count)d». Это обход, а не решение, и честнее сказать так,
чем ждать от каталога того, чего в нём нет.

## Почему язык — это папка, а не файл

Внутри `locale\de\` лежит сколько угодно файлов `.json`, по одному на раздел, и при чтении они
сливаются в один словарь. Это не украшательство. **Новый раздел приходит новым файлом**, и ни один
существующий при этом не переписывается: двое, добавляющие два раздела, не сталкиваются в одном
файле, и следующая версия программы не трогает то, что было переведено месяц назад. Один огромный
`de.json` сделал бы любую правку правкой одного и того же файла, а любое слияние — дракой за него.

Код умеет прочитать и одиночный `locale\de.json` — для языка, которому делиться не на что, — но
поставляется раскладка только папками, и проверка этого требует. Делай папку.

Имя файла совпадает с приставкой ключей внутри него: `serve.json` держит ключи `serve.*`. Код этого
не требует, потому что всё равно сливает всё в один словарь; требуют люди, потому что иначе строку
не найти.

## Файлы разделов

| Файл | Что в нём |
|---|---|
| `assets.json` | Собственные файлы страницы: что говорится, когда одного из них нет. |
| `catalog.json` | Обзор мешей: такой записи нет, обходить нечего. |
| `cbpc.json` | Настройки физики CBPC: шапка, которая пишется в файлы, и вердикты проверки готовых. |
| `cli.json` | Командная строка: строка вызова, каждая строка `--help`, заголовки столбцов и отказы. Самый большой файл, и с большим отрывом. |
| `colliders.json` | Капсулы столкновений: чтение их из скелета, посадка по коже, запись обратно. |
| `config.json` | Настройки: неверный путь к PyNifly или PyNifly, которого нигде нет. |
| `core.json` | Отказы ядра: все части скрыты, неизвестный движок физики, пустой набор ползунков. |
| `environment.json` | MO2, usvfs и корни игры. Сегодня пуст: слой отвечает «да» или «нет» и отдаёт пути, а сообщение пишет тот, кто его позвал. Файл существует, чтобы первому тексту раздела было куда лечь. |
| `journal.json` | Журнал: неизвестный уровень, отвалившийся приёмник, отсутствующий поток. Сами имена уровней (`debug`, `info`, `warn`, `error`) — настройки, а не тексты, и в любом языке остаются английскими. |
| `launcher.json` | Окно `morphbench.exe` — его читает само окно, см. ниже. |
| `model.json` | Меш: нет такой части, нет файла морфов, файл слишком старой версии, чтобы программа его поняла. |
| `page.json` | Страница-смотрелка в браузере: заголовки разделов, кнопки, пояснения и отказы, которые показывает её скрипт. |
| `release.json` | Что печатает `release.py`, пока собирает архив выпуска. См. [building.ru.md](building.ru.md). |
| `serve.json` | Локальный сервер: что он говорит о порте и чем отказывает на запрос. |
| `smp.json` | Настройки Faster HDT-SMP: шапка собранного XML и вердикты проверки готового файла. |
| `text.json` | Таблицы для консоли: заголовки, вердикты и надпись под пустой таблицей. |
| `view.json` | Состояние показа: камера, свет, раскраска. |

Два файла из этого списка читаются странно — из-за того, куда попадают их слова. В `cli.json` лежит
текст `--help`, а он собирается в тот момент, когда строится разборщик команд, а не когда его
печатают: язык к этому времени уже выбран, поэтому `python mb.py --help` выходит на твоём языке.
В `text.json` живут собранные вручную таблицы, и это тот самый файл, где важны ширины.

## Два места, устроенных иначе

Всё, что выше, — один механизм: код называет ключ, каталог отдаёт строку. Два потребителя
воспользоваться им напрямую не могут, и оба решают это тем, что читают те же самые файлы по-своему.

### Страница в браузере

Страница работает в браузере, по другую сторону провода, и спросить питоновский каталог ни о чём не
может. Поэтому **весь раздел `page.` едет внутри полезной нагрузки** — блока JSON, вложенного
в страницу, — уже на языке этого запуска, а скрипт читает его как `T.someKey`. Ключ `page.secView`
из твоего файла становится в скрипте `T.secView`. Подстановка там та же, по имени `%(name)s`, и
делает её маленькая вспомогательная функция в коде самой страницы.

Для переводчика отсюда три следствия:

* Страница, сохранённая командой `mb.py web`, несёт свои тексты внутри навсегда. Это один
  самодостаточный файл, который открывается прямо с диска, так что язык у него остаётся тот, на
  котором его сохранили; чтобы язык сменился, поменяй настройку и сохрани страницу заново.
* Две подписи стоят в самой разметке, а не в полезной нагрузке: подсказка про мышь и строка,
  которая показывается, когда у браузера нет WebGL2 (`page.hint` и `page.noWebGL`). Вторую читают
  ровно тогда, когда скрипт не отработал, — потому она и не может лежать в словаре скрипта.
* Страница ещё и объявляет свой язык браузеру — `<html lang="de">`. Именно это говорит браузеру,
  как переносить слова, какой шрифт брать и как читать текст вслух. С раскладкой справа налево
  не сделано ничего, и она не проверялась.

Сама страница давно не одна строка в коде. Это файлы: `web\page.html`, `web\style.css` и
`web\js\core.js`, `shapes.js`, `view.js`, `bench.js`, `render.js`, `panel.js`, `app.js`, `boot.js`.
`presenters\assets.py` собирает их двумя способами: сервер отдаёт их по одному по адресам
`/web/...`, а `save()` складывает всё в тот самый самодостаточный файл. Порядок загрузки объявлен
один раз, в `PageAssets.SCRIPTS`. Переводимых строк в этих файлах нет ни одной — все они обращаются
к `T`. Что делает каждая панель, написано в [page.ru.md](page.ru.md).

### Окно запуска

`morphbench.exe` — это окно, которое запускает MO2. Своего Python у него нет: это программа на C#,
которая поднимает сервер и показывает его состояние, — поэтому **файлы локализации она читает
сама**, своим кодом, по тем же правилам. `MORPHBENCH_LANG` сильнее настройки `language`, `auto`
означает язык Windows, все `locale\<язык>\*.json` сливаются в один словарь, ключ с `#` — заметка,
а ключ без строки откатывается на английский и затем на самого себя.

Что это значит на деле:

* **Чтобы перевести окно, пересобирать ничего не нужно.** Тексты читаются из `locale\` рядом с exe
  при запуске; в сам файл вшит только значок. См. [building.ru.md](building.ru.md).
* Каталог окно читает один раз, когда открывается. Язык, сменённый при работающем окне, увидится
  после перезапуска.
* В `launcher.json` пиши простой `%(name)s`: ширины и форматы чисел там игнорируются, а удвоенный
  `%%` показался бы как есть.
* Если каталог не прочитается целиком, окно всё равно откроется и покажет ключи. Так задумано:
  не запускающийся лаунчер — это неисправность, а сломанная установка — ровно тот случай, когда
  человеку нужно прочитать ошибку.

## Как проверить работу

Запусти программу на своём языке и почитай таблицы. Это и есть настоящая проверка:
[quickstart.ru.md](quickstart.ru.md) проводит по первому часу, [cli.ru.md](cli.ru.md) перечисляет
все команды.

Что осталось непереведённым — списком ключей:

```
python -c "from morphbench.i18n import Catalogue as C; print('\n'.join(sorted(set(C('en').base) - set(C('de').texts))) or 'nothing left')"
```

Какие языки программа видит и прочитался ли твой без нареканий — последнее значение это
столкновение ключей либо нечитаемый файл, а `None` означает, что всё в порядке:

```
python -c "from morphbench.i18n import Catalogue; c = Catalogue('de'); print(c.available(), c.language, len(c.texts), c.problem)"
```

Про один пробел надо сказать честно: столкновение ключей каталог у себя записывает, но при обычной
работе его пока никто не печатает. Сегодня эта однострочная команда — единственный способ его
увидеть.

В наборе проверок есть раздел про каталог. Он смотрит, что каждый язык покрывает ровно те же ключи,
что и английский, что имена `%(...)` в разных языках совпадают, что ключи — метки, а не фразы, и
что код не называет ни одного ключа, которому нет текста:

```
python tests/run.py test_i18n.py
```

Проверки идут по-английски, на какой бы машине ни запускались, — чтобы пройденное у одного было
пройденным и у другого.

## Как выпустить язык

В архив выпуска попадает `locale\*\*.json`, поэтому новая папка подхватывается без единой правки
в сборке — [building.ru.md](building.ru.md) рассказывает, что туда идёт ещё и под какой лицензией.
`morphbench.json` в архив намеренно не кладут: он создаётся при первом запуске, и потому язык —
единственная настройка, которую новому пользователю приходится вписывать руками.

Одно отличие перевода «для себя» от перевода, который отдают в проект: проверка выше требует
от отданного языка покрыть **каждый** ключ, потому что дыра в репозитории — это дыра, которой никто
не замечает. Для себя же неполная папка совершенно нормальна: недостающие строки просто выйдут
по-английски.

Назад в [README.ru.md](../README.ru.md).

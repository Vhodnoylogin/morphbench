# `launcher\` — точка входа для Mod Organizer 2

English version of this file — [README.md](README.md).

MO2 подменяет файловую систему только процессам, которые запустил сам: моды сводятся
в один игровой `Data` библиотекой usvfs. Чтобы увидеть меши всей сборки, верстак должна
запустить **сама** MO2, а она запускает исполняемые файлы, а не скрипты. `morphbench.exe` —
как раз такой файл: небольшое окно с состоянием сервера, корнем обзора и кнопками поднять,
остановить и открыть страницу. Запущенное из MO2, оно поднимает `python mb.py serve` своим
потомком, и тот видит сведённый `Data`.

| Файл | Что это |
|---|---|
| `morphbench.cs` | окно на C# — целиком |
| `morphbench.manifest` | осведомлённость о DPI и общие элементы управления, вкомпилированные внутрь |
| `build.cmd` | собирает `..\morphbench.exe` штатным компилятором .NET Framework; ASCII и CRLF — намеренно |
| `make-icon.py` | рисует `morphbench.ico`; `morphbench.png` — его предпросмотр и продукт сборки |

Собирается один раз: `launcher\build.cmd`. Результат ложится рядом с `mb.py` и в git
не попадает — это продукт. Исключение — `morphbench.ico`: он версионируется через Git LFS,
потому что эти байты едут внутри exe и без них рецепт его не пересоберёт.

## Может зависеть от

**HTTP-API сервера и командной строки.** Всё, что делает кнопка, делает и командная строка:
`serve --status`, `serve`, `serve --stop`, `/api/root`, открыть страницу. Больше отсюда
до верстака ничего не достаётся — окно такой же клиент, как и все.

Ни одного пути внутрь не вписано. Модуль лежит рядом с exe, или его папку дают доводом,
или называет `MORPHBENCH_HOME`; python — это `MORPHBENCH_PYTHON`, ключ `python`
в `morphbench.json`, `python.exe` в PATH (кроме заглушки из магазина Windows), ключ реестра
`PythonCore` или пускатель `py.exe`.

## Кто не вправе его импортировать

Никто и не может: это отдельная программа на другом языке. Зависимость идёт в одну сторону —
окно зовёт верстак, а верстак об окне не слышал.

## Правило, которое решает, что здесь лежит

**Окно ничего не считает и ничего не знает про меши.** Разбор доводов и оконный обиход —
и только. Кнопка, умеющая то, чего не умеет `mb.py`, — та же поломка, что и управление
на странице, до которого не дотянуться из командной строки.

**Окно — удобство, а не условие.** Запись в MO2, у которой двоичный —
`<morphbench>\python\python.exe`, а доводы — `mb.py serve`, делает ту же работу: usvfs
внедряется так же, и сервер видит тот же сведённый `Data`. Кто предпочитает не запускать
неподписанный двоичный, теряет только кнопки, — поэтому ничто и никогда не должно начать
работать только через эту папку.

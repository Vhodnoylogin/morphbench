# `presenters\` — слои, показывающие то, что посчитало ядро

English version of this file — [README.md](README.md).

Слой показа превращает готовые числа в то, что может взять человек или другая программа:
таблицу в консоли, PNG, страницу в браузере, файл настроек в чужом формате.

| Файл | Что показывает |
|---|---|
| `text.py` | таблицы и сводки для командной строки |
| `raster.py` | кадр в PNG и лист из нескольких ракурсов (`pillow`) |
| `web.py`, `assets.py` | смотрелку: полезную нагрузку, из которой она собирается, и файлы `..\web\` — либо отданные по одному, либо свёрнутые в один самодостаточный файл |
| `serve.py` | локальный сервер: страницу со списком мешей и HTTP-API, которым правит окно запуска |
| `ppb.py`, `smp.py`, `cbpc.py` | форматы настроек чужих модов — тела столкновений PPB, качающаяся физика SMP и CBPC |

## Может зависеть от

**Фасада `MorphBench` и ничего больше из ядра.** Плюс то, что нужно конкретному способу
показа: `pillow` в `raster.py`, `http.server` в `serve.py`. Обиход — `i18n`, `journal`,
`config` — общая земля, им пользуются свободно.

## Кто не вправе его импортировать

**Ничто из `morphbench\` не импортирует слой показа.** Ядро не знает, что способ показать
его ответы вообще существует; зависимость идёт в одну сторону.

## Правило, которое решает, что здесь лежит

**Слой показа, который считает, — это заявка на поломку фасада.** Если ради показа число
приходится вычислять, вычисление принадлежит ядру, а число — ответу фасада. Этим и держится
свойство, ради которого всё затевалось: всякое действие страницы — одноимённый вызов фасада,
поэтому любой сеанс воспроизводится из командной строки. Потому страница и печатает внизу
своей панели равнозначную строку `mb.py render`.

Форматы чужих модов живут здесь и только здесь (`ppb`, `smp`, `cbpc`): ядро знает величины,
а слой — в какие строки и теги они лягут.

# Переносимая установка и Root Builder

Application 0.8.7 использует новую структуру с Morphbench Launcher v3.
Версии независимы; Application сохраняет адаптеры выпущенных v1/v2.
Прежние плоские установки 0.8.0 поддерживаются; переносите их в новую папку.

**GitHub:** `morphbench-0.8.7-win64.zip` уже содержит Launcher и Application.
Распакуйте его один раз; вторая обязательная загрузка не нужна. С Root Builder
установите его одним включённым модом. **Nexus:** установите два Main-файла, как ниже.
Необязательный ZIP с исходниками Nifly предназначен разработчикам и не устанавливается.
Существующую установку обновляйте через обновлятор Application и описанные ниже шаги
перехода; распаковка полного ZIP поверх старой установки не заменяет обновлятор.

```text
Morphbench/
  launcher/                  EXE, Python, vendor и диспетчер запуска
    morphbench.exe
    mb.py
    runtime-manifest.json
  app/                       приложение, браузер, документация, обновление
    mb.py
    update.py
    morphbench.json          настройки пользователя, не принадлежат пакету
  plugins/                   аддоны, их реестр и поколения
  application-manifest.json  состав App и совместимость API/ABI Runtime
```

Оба ZIP начинаются с `root/Morphbench/`. При ручной установке скопируйте `Morphbench`
из `root` в папку инструментов с правом записи или рядом со SkyrimSE.exe / SkyrimVR.exe.
Запускайте `Morphbench/launcher/morphbench.exe`. Саму папку `root` не кладите в корень
игры; эти файлы также не предназначены для Data.

Для MO2 [Kezyma's Root Builder](https://www.nexusmods.com/skyrimspecialedition/mods/31720)
**необязателен**: он размещает содержимое `root/` в корне игры. Установите оба ZIP
как два отдельных включённых мода, сохранив `root/Morphbench`. Application должен стоять
ниже Launcher в левой панели MO2, с большим приоритетом, чтобы его диспетчер и переводы
побеждали после будущих обновлений App. Перед запуском выполните сборку Root Builder.
В MO2 укажите `Morphbench/launcher/morphbench.exe` из корня игры.
Запуск через MO2 даёт доступ к виртуальной Data. Одна VFS для Data не переносит файлы
в корень игры. Ручной установке или внешней папке инструментов Root Builder не нужен.

В обоих пакетах одинаковые небольшой Python-диспетчер и переводы ланчера. Это позволяет
запускать Launcher из физической папки отдельного мода MO2, когда App находится отдельно.
Эти файлы принадлежат App. Перечень каждого выпущенного Runtime неизменяем. Launcher v3
имеет собственный нативный идентификатор; одобрение антивируса этим не гарантируется.

Диспетчер использует явно заданную абсолютную папку `MORPHBENCH_APP`, затем соседнюю
`../app`. Иначе он проверяет корни игры среди родительских папок и зарегистрированных
установок Skyrim: ищет `Morphbench/app` с метаинформацией установки. Нужен единственный
полный кандидат; при нескольких установках выдаётся ошибка неоднозначности. Он не выбирает
SE вместо VR по порядку, не сканирует диски и не разрешает виртуальные пути в отдельные
моды. App использует Runtime запущенного ланчера; `plugins` находится рядом с `app`.
Явная непустая настройка `addonDirectory` сохраняет своё поведение.

С Root Builder 5.1.1 указывайте **EXE из развёртывания в корне игры**, если нужны аргументы
`--start` или `--root`. Его перенаправление EXE из физического источника мода не передаёт
эти аргументы надёжно. EXE из источника по-прежнему может открыть обычное окно лаунчера.

Пользовательские флаги EXE сохранены: `--start` и `--root` работают как прежде.
`MORPHBENCH_APP` — переменная окружения процесса для неоднозначной установки.
Окно, параметры, поиск и сервер принадлежат Application. Хост v3 только запускает
комплектный Python/shim, ждёт завершения и возвращает код выхода. При запуске проверяются
API/ABI Runtime, запрошенный протокол хоста, хеши файлов и встроенный Python.
Совместимый Runtime не требует нового выпуска Application.

## Обновления и прежние установки

Закройте сервер и ланчер. Из папки `Morphbench` выполните:

```powershell
.\launcher\python\python.exe .\app\update.py --check --package "C:\Downloads\application.zip" --json
.\launcher\python\python.exe .\app\update.py --package "C:\Downloads\application.zip" --json
```

Заменяются только учтённые файлы App, диспетчер и переводы ланчера. Настройки, `plugins`,
состояние ланчера, экспорты и Runtime сохраняются. Указание `Morphbench` или `Morphbench/app`
использует одну блокировку и журнал восстановления. Для восстановления замените
`--package` на `--recover`.

Обновляйте постоянный источник мода MO2 и затем пересобирайте развёртывание Root Builder.
Не обновляйте временное развёртывание, которое Root Builder затем очистит. Сначала сохраните
изменения настроек и плагинов обратно в источник через синхронизацию Root Builder. Если App
и Launcher — разные моды, распакуйте App поверх его `root/Morphbench` либо используйте
обновление с доступным соседним Runtime. Очистка временного развёртывания не входит
в гарантии сохранности автономного обновления Morphbench.

Плоская установка продолжает использовать старый EXE, настройки и `addons` или явный путь;
для неё поддерживаются плоские обновления. Смена структуры обновлением поверх запрещена.
Для переноса сохраните старую установку и распакуйте новые ZIP в новую папку. Скопируйте
`morphbench.json` в `app`, состояние ланчера в `launcher`, весь каталог аддонов с реестром
и поколениями в `plugins`. Очистите `addonDirectory` для нового пути по умолчанию или явно
оставьте свой путь. Как и раньше, относительный пользовательский путь считается от рабочей
папки процесса (обычно `launcher` при запуске EXE); абсолютный путь однозначно сохраняет
внешний реестр. Автоматического перемещения или сброса существующей установки нет.

## Переход с Application 0.8.6 / Launcher v2 на v3

Application 0.8.6 не содержит адаптера минимального хоста v3. Остановите сервер и
закройте Launcher. **Сначала обновите Application до 0.8.7** командами проверки/обновления
выше через Python установленного v2. Новая App работает и с v2. Сохраните копию для отката,
замените старую папку `launcher` чистой папкой v3 и верните только
`morphbench.launcher.json`, если он существует. Сохраните `app/morphbench.json` и `plugins`;
не смешивайте старые нативные и служебные файлы с v3. Запустите и проверьте своё состояние.
С Root Builder сохраните состояние и обновите постоянные источники до пересборки.
Можно также установить оба пакета в новую папку и перенести пользовательское состояние.

## Первый переход с Application 0.8.5 / Launcher v1

Остановите сервер и закройте окно. Сохраните резервную копию. Распакуйте новый архив
Application во временную папку и запустите **новый** установщик старым встроенным Python:

```powershell
& "<старый Morphbench>\launcher\python\python.exe" "<распакованный App>\root\Morphbench\app\update.py" --target "<старый Morphbench>" --package "<новый ZIP Application>" --check --json
& "<старый Morphbench>\launcher\python\python.exe" "<распакованный App>\root\Morphbench\app\update.py" --target "<старый Morphbench>" --package "<новый ZIP Application>" --json
```

Установщик 0.8.5 не читает схему 2. Новый читает старую установку, транзакционно удаляет
устаревшие файлы App из её перечня и сохраняет настройки/плагины. Сначала обновите App
до 0.8.7: адаптер v1 сохранён. Затем замените папку `launcher` чистой v3, как описано
выше, перенеся только собственный `morphbench.launcher.json`, если он существует.
Сохраните любое прежнее нестандартное имя состояния в копии для отката до проверки.
Не добавляйте старые нативные и служебные файлы в v3. Исторический переход на схему 2/v2
появился в Application 0.8.6; промежуточная установка 0.8.6/v2 сейчас не требуется.

При отдельных модах MO2 сохраните пользовательские файлы, замените постоянные источники
пакетов и пересоберите Root Builder. Application должна перекрывать общие shim/переводы.
Можно собрать новую структурированную папку из обоих архивов и перенести своё состояние.
Позднейшие совместимые Launcher и их новые хеши принимаются без нового выпуска App.
Обычные обновления App используют установленный обновлятор.

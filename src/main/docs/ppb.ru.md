# Существующие настройки капсул PPB

English version — [ppb.md](ppb.md).

Morphbench загружает существующий `PPB_tuning.txt`, показывает поддерживаемые числовые поля
капсул и экспортирует изменённый **новый файл**. Редактор сохраняет комментарии, порядок команд,
повторяющиеся команды, неизвестный текст, BOM UTF-8 и исходные переводы строк. Правка заменяет
только участок исходного текста с выбранным десятичным числом. Экспорт без правок точно
воспроизводит загруженный текст UTF-8.

Эти средства находятся в **Коллайдеры → Правка капсул**, рядом с загрузкой источника
и сохранением. PPB — источник настроек общего редактора капсул, а не отдельная вкладка.
Ссылки и рецепты, выбирающие прежнюю вкладку PPB, теперь открывают Правку капсул с сохранением
исходных данных и изменений.

Игровой плагин PPB предназначен для **Skyrim VR**. Редактировать его текст можно без запуска
любой версии игры, но SE/AE не выполняет динамическое масштабирование и автоподгонку PPB.
Статический экспортированный скелет Havok можно проверять отдельно в совместимой игре;
функции PPB от этого не появляются. TRI-морфы видимой модели и геометрия капсул Havok
независимы: изменение меша само по себе не подгоняет капсулы. У CBPC и FSMP также есть
собственные описания коллизий.

Выберите существующую капсулу NIF в общем редакторе, откройте файл настроек и выберите запись
источника для связи с этой капсулой. Второго списка выбора капсулы NIF нет. Связь остаётся
явной: проверьте выбранное тело, сторону, форму и систему координат перед использованием
результата. Редактор не находит соответствующую кость, не преобразует координаты между разными
телами и не создаёт отсутствующий дочерний элемент списка. Дополнительные средства источника
сохраняют две операции одностороннего копирования концов A и B и радиуса в игровых единицах
локальной системы тела. Число `Enable` редактируется отдельно; копирование геометрии не
включает переопределение во время игры. Сессия сохраняет исходный документ и числовые правки
для повторного воспроизведения.

## Визуальная правка исходника

Выберите полную запись источника и свяжите её с редактируемой капсулой, выбранной в общем
редакторе. Сначала геометрия этой записи копируется в выбранную капсулу рабочей копии.
Подпись источника показывает обе стороны связи; она не означает, что PPB выберет эту капсулу
в игре. Одновременно действует одна связь.

Перемещайте связанную капсулу с Shift и левой кнопкой мыши либо тяните её центральную ручку.
Это меняет шесть координат концов в исходнике. В редакторе капсул также можно менять концы
и радиус; правка активных геометрических полей PPB сразу обновляет изображение. Правка
только радиуса не переписывает остальные числовые фрагменты. `Enable`, прежние дубликаты
команд и другие записи остаются отдельными. Для связи нужны положительный радиус и числа,
представимые в формате PPB; отвергнутая правка сохраняет прежние текст и геометрию.

Разъединение прекращает синхронизацию без отмены изменений. Успешная
замена исходника или скелета, сброс капсул, подгонка, дублирование и удаление тоже завершают
связь: она не переходит незаметно на перенумерованную капсулу списка. Правка другой капсулы
не меняет связанную запись. Рецепт восстанавливает итоговые значения и явную связь с проверкой
исходного скелета. Экспортируйте настройки и, при необходимости, рабочий NIF в новые файлы.
Связывание и экспорт не меняют файлы установленных модов.

Для автоматизации доступны те же методы фасада: `ppb_link(capsuleId,bone,index)` и `ppb_unlink()`.
`ppb_state().binding` равно null либо `{capsule,bone,index}`. При связи обычные `ppb_set`,
`collider_set` и `collider_translate` согласованно меняют оба состояния.

## Поддерживаемая часть формата

Адаптер распознаёт регистрозависимую запись
`cap<Slot>[C<number>]<Parameter> <decimal>` для `Enable`, `AX`, `AY`, `AZ`, `BX`, `BY`, `BZ`
и `R`. Поддерживается десятичная экспоненциальная запись. Комментарии и другой текст после
числа сохраняются на месте. Блок без суффикса имеет индекс 0. Проверенные предельные суффиксы:

| Слот | Наибольший суффикс |
|---|---:|
| Hand | C7 |
| Fore | C3 |
| Upper | C5 |
| Head | C34 |
| Spine0 | C12 |
| Spine1 | C13 |
| Spine2 | C24 |
| Neck | C1 |
| Thigh | C9 |
| Calf | C6 |
| Foot | C5 |
| Com | C37 |

Неизвестные имена, `C0`, суффиксы с ведущим нулём вроде `C01` и суффиксы сверх таблицы остаются
неразобранным текстом. Для копирования геометрии нужны все восемь поддерживаемых полей с
однозначной числовой записью. Текущий радиус должен быть положительным. Отсутствующие поля не
заполняются значениями по умолчанию из плагина или предыдущей загрузки во время игры.
Неконечные числа, переполнение float и неоднозначные числовые префиксы вроде `1foo` остаются
неразобранным текстом и запрещают копирование геометрии этой исходной группы.

Ключи парсера PPB глобальны и чувствительны к регистру. Строка, похожая на заголовок раздела,
не создаёт новую область действия. При повторении успешно разобранного ключа действует
последнее присваивание; редактор сохраняет все вхождения и отмечает действующее поле.
Некорректные присваивания вызывают предупреждение вместо догадки об их смысле. PPB не удаляет
BOM UTF-8: первая команда с BOM перед именем сохраняется, но не считается действующей.
BOM перед первым комментарием не мешает последующим строкам.

У Hand особая нумерация: `capHandC1` адресует дочерний элемент списка 0, `C2` — элемент 1 и
так далее. Блок `capHand` без суффикса адресует одиночную капсулу. У остальных слотов блок
без суффикса адресует главную капсулу/элемент списка 0, а `C1` — элемент 1. Наличие
поддерживаемого параметра не доказывает наличия этого элемента в выбранном скелете.

## Строки настроек после подгонки

`mb.py fit ... --ppb` создаёт новые присваивания капсул; редактор существующего документа,
сохраняющий исходный текст, при этом не используется. У PPB один общий набор для точных правых
и центральных узлов, без независимых левых/правых наборов. Выберите точный поддерживаемый
источник, например `--find "NPC R Thigh [RThg]"`. Двусторонние/только левые входы и повторные
общие слоты отклоняются с пояснением: экспортёр не выбирает победившую сторону и не угадывает
`capMirrorL`. Кости без слота PPB, например хвост, по-прежнему пропускаются. Похожие имена
с другим суффиксом в скобках отклоняются: идентификатор игрового узла PPB должен быть точным.

Создаваемым ключам нужна одиночная капсула либо известный плоский список дочерних капсул
в проверенных пределах выше. Список Hand с одним элементом использует `capHandC1`, а одиночная
капсула Hand — `capHand`. При правке/экспорте исходного списка NIF с одной капсулой его структура
списка сохраняется. Неизвестные, вложенные, обёрнутые и некапсульные исходные структуры
отклоняются текстовым экспортом; явная правка NIF может создать новую поддерживаемую структуру.

Фасад `collider_local` сохраняет округлённый отчёт `capsules` и добавляет точную геометрию
`capsuleGeometry`, структуру выходной формы `shapeKind` и исходные/известные создаваемые
`shapeChildren`. Текстовый экспорт использует точные значения с обратимостью float PPB;
некорректные числа, переполнение, обнуление слишком малых значений и неположительный радиус
отклоняются. При `--ppb --out` проверка завершается до записи нового скелета. Созданные строки
описывают исходные значения: игровое зеркалирование, автоподгонка, ограничения персонажа/sculpt
и прочие переопределения ниже по-прежнему требуют проверки.

## Что требует свидетельств из работающего PPB

Предпросмотр и копирование описывают исходные значения. Они не вычисляют итоговые игровые
капсулы. PPB может подавлять или заменять глобальные значения через выбор цели sculpt и
переопределения `npcCap` в `PPB_skeletons.txt`, пол актёра, правила голов звериных рас, наличие
дочерних форм, автоподгонку и этапы изменения масштаба/формы. Sculpt сравнивает имя файла
скелета пола самого актёра; в исходниках остались старые комментарии только о женском
скелете. Приоритет имеет реализация. `Enable > 0.5` разрешает глобальный параметр, но
`Enable 0` не подавляет отдельное правило `npcCap`.

Для парных конечностей `capMirrorL` зеркалит допустимые правки правой стороны, меняя знак
локальной X у обоих концов и сохраняя радиус. Центральные слоты не зеркалятся. `capAutoFit`
может управлять положением концов. Оба управляющих параметра сохраняются и показываются как
наблюдения исходного файла только для чтения; редактор их не исполняет и не подставляет
значения отсутствующих параметров.

## Происхождение и граница участия

Таблица формата и ограничения проверены по
[коммиту Precision Physic Bodies e26b4eb](https://github.com/Telord72612/Precision-Physic-Bodies/tree/e26b4ebc8061e8736b344e4f3e9216dea9254747).
Основные источники:
[Tuning.cpp](https://github.com/Telord72612/Precision-Physic-Bodies/blob/e26b4ebc8061e8736b344e4f3e9216dea9254747/src/Tuning.cpp)
(`Index`, `ReloadGrabTune`, `CapFixChildSlot`) и
[CapFix.cpp](https://github.com/Telord72612/Precision-Physic-Bodies/blob/e26b4ebc8061e8736b344e4f3e9216dea9254747/src/CapFix.cpp)
(`WriteCapsule`, `MirrorVals`, `SculptAllowsSlot`, `ApplyListSlot`).

Morphbench отвечает за загрузку без потерь, редактор, явное копирование, воспроизведение сессий
и экспорт в новый файл. Полезный вклад Telord — проверить поддерживаемый формат и игровые
ограничения, затем предоставить представительный пример с точными входными настройками и
скелетом, контекстом актёра и ожидаемыми капсулами в мировых координатах. Будущему предпросмотру
итогового игрового состояния нужны эти свидетельства и объявленная версия плагина.
Синтетические проверки редактора подтверждают сохранность текста и ограниченный разбор;
они не подтверждают поведение столкновений в Skyrim.

# Установка и обновление morphbench

English version — [updating.md](updating.md).

Скачайте **Application 0.8.8** (основной файл) и **Morphbench Launcher v3**.
Их версии независимы. Application проверяет совместимость API 1 / CPython 3.12 Windows
x64 и целостность Runtime отдельно. Launcher v3 требует адаптера протокола хоста 1,
добавленного в Application 0.8.7. Минимальный EXE запускает комплектный Python; окно
и сервер принадлежат Application. Отдельные Python и Blender не нужны.

Разделение позволяет не перезагружать те же нативные бинарники и не повторять их карантинную
проверку при каждом обновлении Application. Каждая загрузка проходит проверки Nexus;
это не одобрение антивируса или освобождение от проверки. Доступны Manual и Mod manager download.

## Первая установка

На GitHub скачайте `morphbench-application-0.8.8.zip` из
[релиза Application](https://github.com/Vhodnoylogin/morphbench/releases/tag/v0.8.8)
и `morphbench-launcher-v3-win64.zip` из отдельного
[релиза Launcher v3](https://github.com/Vhodnoylogin/morphbench/releases/tag/launcher-v3).
На Nexus скачайте оба Main-файла. Если Launcher v3 уже установлен, достаточно обновить
Application. Оба архива начинаются с `root/Morphbench/` и объединяются в:

```text
Morphbench/
  launcher/                  EXE, Python, vendor и диспетчер запуска
    morphbench.exe
    mb.py
    runtime-manifest.json
  app/                       приложение, браузер, документация, обновлятор
    mb.py
    update.py
    morphbench.json          создаваемые настройки пользователя
  plugins/                   установленные аддоны и состояние
  application-manifest.json
```

- **Вручную:** объедините `Morphbench` из папок `root` обоих архивов в одной папке
  инструментов с правом записи или корне игры рядом со `SkyrimSE.exe` / `SkyrimVR.exe`.
  Например, результат — `D:\Tools\Morphbench`, а не `D:\Tools\root\Morphbench`.
  Запускайте `launcher\morphbench.exe`.
- **MO2:** установите ZIP как два отдельных включённых мода, сохранив `root/Morphbench`.
  Установите необязательный [Kezyma's Root Builder](https://www.nexusmods.com/skyrimspecialedition/mods/31720).
  Application должен стоять ниже Launcher в левой панели, с большим приоритетом.
  Соберите корневое развёртывание через Root Builder, добавьте
  `Morphbench\launcher\morphbench.exe` из корня игры в MO2 и запускайте через MO2.

При ручной/внешней установке Root Builder не нужен. Обычная VFS для Data не размещает
корневые файлы: архивы нельзя устанавливать как обычное содержимое `Data`. На Nexus оба
пакета — Main Files, Application — Primary; доступны Manual и Mod manager download.
Структура и автоматический поиск App, когда Launcher находится в физическом источнике мода,
а App/plugins — в корне игры, описаны в [install-layout.ru.md](install-layout.ru.md).

## Обновление прежнего Launcher до v3

**Перед установкой Launcher v3 сначала обновите Application до 0.8.8** (минимум: 0.8.7). В Application
0.8.6 нет его адаптера. Остановите сервер/окно, обновите App через Python установленного
v1/v2, затем замените только папку `launcher` чистой папкой v3, сохранив
`morphbench.launcher.json`. Сохраните `app/morphbench.json` и весь каталог `plugins`.
Не добавляйте устаревшие нативные файлы в новый Launcher. Application 0.8.7 сохраняет
адаптеры v1/v2, поэтому App обновляется первой. С App 0.8.5 используйте новый распакованный
обновлятор; [точные шаги](install-layout.ru.md). С Root Builder обновляйте постоянные
источники модов и сохраняйте состояние до пересборки развёртывания.

## Обновление Application

Храните скачанный ZIP вне установки. Сохраните работу, остановите сервер и закройте
лаунчер. Из `Morphbench` выполните остановку, проверку и обновление:

```powershell
.\launcher\python\python.exe .\launcher\mb.py serve --stop
.\launcher\python\python.exe .\app\update.py --check --package "<application.zip>" --json
.\launcher\python\python.exe .\app\update.py --package "<application.zip>" --json
```

`--check` проверяет без применения изменений; может создавать/использовать блокировку.
Проверьте версию, требуемый Runtime и результат. Цель по умолчанию определяется по
`update.py`, а не рабочей папке. `Morphbench` и `Morphbench/app` выбирают одну установку.
`--target "<install>"` нужен только для явного выбора другой установки.

Обновлятор проверяет совместимость API/ABI Runtime, списки и установленные учтённые файлы.
Изменённые учтённые файлы и одновременные обновляторы отклоняются. Работающая Application
держит совместную блокировку, обновлению нужна исключительная. Дождитесь завершения перед запуском.

С Root Builder **обновляйте постоянный источник мода MO2**, затем пересобирайте развёртывание.
Перед очисткой синхронизируйте изменённые настройки/плагины обратно в постоянный источник
и проверьте, куда Root Builder их сохранил. Сборка/синхронизация/очистка не входят в гарантии
автономного обновлятора. При отдельных модах Launcher/App распакуйте ZIP App поверх его
`root/Morphbench`, сохраняя `app/morphbench.json` и `plugins`, либо обновляйте полную
постоянную установку с доступным соседним Runtime. Источник только с App не пройдёт
проверку Runtime автономным обновлятором.

## Сохранность и восстановление

Заменяются только учтённые файлы App, диспетчер запуска и переводы лаунчера.
Устаревший файл удаляется, только если раньше принадлежал App. Обновлятор сохраняет
`app/morphbench.json`, `launcher/morphbench.launcher.json`, `plugins` с реестром,
поколениями/состоянием/сеансами, произвольный `addonDirectory`, экспорты, неизвестные файлы
пользователя и исходный нативный Runtime. Оба пакета намеренно повторяют одинаковые
диспетчер и переводы лаунчера, принадлежащие App: так запускается отдельно размещённый Launcher.

Обновление использует резервные копии и журнал, без атомарной замены всей папки.
При прерывании оставьте Application остановленной, сохраните журнал/копии и восстановите из `Morphbench`:

```powershell
.\launcher\python\python.exe .\app\update.py --recover --json
```

Запускайте программу только после успешного восстановления, затем проверьте/повторите пакет.
При конфликтах или отсутствии копий сохраните установку и отчёт. Не меняйте манифесты ради обхода проверки.

## Прежние плоские установки и перенос

В опубликованной 0.8.0 EXE, `mb.py`, `python`, `vendor`, настройки и `addons` лежат рядом.
Такая установка поддерживается и принимает **плоские** пакеты Application:

```powershell
.\python\python.exe .\update.py --check --package "<flat-application.zip>" --json
.\python\python.exe .\update.py --package "<flat-application.zip>" --json
```

Обновление между структурами запрещено. Для переноса плоской раздельной установки или прежнего полного архива:

1. Остановите программу и сохраните старую папку нетронутой.
2. Установите оба новых пакета в **новую папку**.
3. Скопируйте `morphbench.json` в `app`, состояние лаунчера в `launcher`, а весь старый
   каталог аддонов с реестром, поколениями и состоянием — в `plugins`.
4. Очистите `addonDirectory` для нового значения по умолчанию или явно сохраните свой путь.
   Относительный путь считается от рабочей папки процесса, обычно `launcher` при запуске EXE;
   для внешнего реестра используйте абсолютный путь.
5. Измените путь исполняемого файла MO2 и проверьте настройки/плагины перед продолжением.

Не накладывайте старые файлы программы. Исходники без манифестов выпуска остаются пригодны
для разработки; обновлятор работает с раздельными установками с манифестами. Изменение EXE
или нативных зависимостей требует нового отдельно проверенного Runtime и соответствующего
манифеста App. Хеш определяет байты, это не подпись или одобрение антивируса/Nexus.
Python/JavaScript остаются исполняемым кодом. Создание пакетов: [building.ru.md](building.ru.md).

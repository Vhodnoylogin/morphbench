# `launcher/` — стабильная точка входа для Mod Organizer 2

English version — [README.md](README.md).

MO2 подменяет файловую систему исполняемым файлам и их потомкам. Разрабатываемый
Launcher v3 только запускает комплектный Python, ждёт завершения и возвращает код
выхода: один класс, два метода. Окно, переводы, параметры, настройки, поиск установки,
диагностика, HTTP и владение сервером — обновляемый код Application.

| Файл | Ответственность |
|---|---|
| `morphbench.cs` | фиксированный запуск интерпретатора/shim и чистое экранирование аргументов Windows |
| `mb.py` | принадлежащие Application shim, поиск установки и адаптеры совместимости |
| `morphbench.manifest` | встраиваемый манифест Windows |
| `build.cmd`, `make-icon.py` | рецепты для разработчика; результат в `target/launcher/` |

Установка сохраняет `root/Morphbench/{launcher,app,plugins}`. Необязательный Root Builder
поддерживает размещение через MO2; вручную извлеките Morphbench из root.
См. [установку](../docs/install-layout.ru.md).

## Фиксированная нативная граница

Единственные нативные точки привязки — `python/python.exe` и `mb.py` рядом с EXE.
Хост открывает их через файловую систему, не использует оболочку/консоль/каналы вывода
и передаёт исходные аргументы, рабочую директорию и окружение в shim. C# не
интерпретирует параметры App, настройки, PATH, реестр, JSON и HTTP.

`presenters/launcher.py` владеет чистыми функциями политики и LauncherSession,
использующим WebServer/ServerLink. `presenters/launcher_window.py` владеет Win32-окном
стандартной библиотеки и последовательным исполнителем/наблюдением за родителем.
Закрытие останавливает только свой сервер в том же процессе.
См. [протокол и переход](../docs/launcher-protocol.ru.md).

Выпущенные файлы Runtime v1/v2 остаются неизменными; их адаптеры App сохраняются.
Перед v3 установите App с протоколом хоста 1: опубликованный App 0.8.6 его ещё не имеет.
Дальнейшие совместимые App обновляют окно/политику без изменения нативного хоста.

## Сборка и работа с исходниками

Из checkout запустите `src/main/launcher/build.cmd`: команда собирает только хост/иконку
в игнорируемый target/launcher/, не скачивает и не выбирает Python. Для запуска EXE
с исходниками разместите рядом python/ и vendor/ закреплённого Runtime, скопируйте
launcher/mb.py рядом с EXE и задайте MORPHBENCH_APP равным абсолютному `<checkout>/src/main`.
Один EXE без комплектного интерпретатора не запускается намеренно. Не изменяйте для
разработки установленный/опубликованный Runtime.

CLI исходников по-прежнему использует системный Python напрямую. Запись MO2 с
комплектным python/python.exe и параметрами `mb.py serve` также поддерживается:
EXE добавляет удобство, а не исключительные возможности.
См. [сборку](../docs/building.ru.md).

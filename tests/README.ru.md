# Проверки

`test_layout_paths.py` проверяет плоские и новые пути без разрешения VFS в физические моды,
выбор библиотек и плагинов, неоднозначность корней игры/реестра и настоящий Python-диспетчер.
`test_structured_distribution.py` проверяет обёртку Root Builder, границы владения файлами,
отказ смене структуры и повреждённым метаданным, общую блокировку и два обновления
с сохранением Runtime, настроек и плагинов. Настоящий запуск MO2/usvfs проверяется отдельно.

English version of this file — [README.md](README.md).

```
python tests/run.py                 все наборы подряд, одна итоговая строка в конце
python tests/run.py test_tri.py     один набор, по образцу имени файла
python tests/test_layers.py         любой файл запускается и сам по себе
```

Только `unittest` из стандартной библиотеки: стороннего фреймворка проверок нет. Проверки лежат
**вне** пакета `morphbench\`, он их не импортирует; корень программы они находят от собственного
расположения.

Язык закреплён: `run.py` и `common.py` оба выставляют `MORPHBENCH_LANG=en`, поэтому проверки
читают английские тексты, на каком бы языке ни говорила машина. Без этого проверка, сверяющая
сообщение слово в слово, у одного человека проходила бы, а у другого падала.

Ни один набор не читает файл из сборки модов: тело собирается в памяти из `Shape`, `Bone`,
`BodyModel`, `Morph`, `MorphSet` (общие сборщики — в `common.py`, вывернутый наружу замкнутый куб —
в `solids.py`) и подключается к фасаду через `MorphBench.attach`. Настройки создаются во временной
папке (`Config(<tmp>/morphbench.json)`), поэтому настоящий `morphbench.json` не трогается; внутри
проверок `mb.py` получает фасад с теми же настройками подменой `mb.MorphBench`. Запуск под MO2
изображается подменой `Environment.inside_mo2`, а игры из реестра — подменой
`Environment.game_roots`: ни одной настоящей папки сборки нигде.

PyNifly ищется ровно так, как его ищет программа: ключ `pynifly` в настройках, иначе аддон
`io_scene_nifly` в папке аддонов Blender. Без него наборы, которым надо записать настоящий файл,
**пропускаются** с названной причиной — пропуск не считается отказом. Отказ самого API PyNifly
при создании файла — тоже пропуск, и он несёт текст исключения: проверяется чтение верстака,
а не PyNifly.

## Проверки скелетов и PPB

`test_ppb_export.py` проверяет точные правые/центральные слоты создаваемых строк PPB, нумерацию
одиночной Hand и её списка, конфликты общих ключей, пределы дочерних форм, точность float,
отклонение неизвестных структур и отсутствие частичного вывода CLI при отказе. Синтетические
NIF, записанные PyNifly, проверяют сохранение исходного списка с одной капсулой после правки,
экспорта и повторного открытия; файлы установленной сборки не читаются.

`test_skeleton_open.py` проверяет точный выбор отдельного NIF, конечные границы пустой геометрии,
кадрирование узлов и капсул, откат неудачной загрузки, строгий JSON и сообщение об ошибке запуска.
`test_ppb_document.py` проверяет сохранение текста PPB, числовые диапазоны исходника, таблицу
частей и номеров, повторы ключей, BOM и неподдержанный синтаксис. `test_ppb_workspace.py`
проверяет явный перенос геометрии, сохранение текста, атомарную проверку документа, изоляцию
экспорта NIF, воспроизведение CLI/HTTP и настоящий браузерный код. Используются синтетические
данные; соответствие поведению PPB в игре этими тестами не подтверждается.

## Проверки режима слотов

`test_slot_variants.py` проверяет три слоя вариантов, совместные центр/радиус, явные равные значения, восстановление v1/v2 и атомарность отказов, удаление источника, копии чтения, неизменность авторских байтов, непривязанные пресеты только с явными полями и CLI с проверкой выходных путей. Node исполняет настоящий JS-владелец/фасад и обработчики SlotsPanel на синтетических данных; это не визуальная проверка браузера.

`test_slots.py` проверяет атомарную валидацию размещений, разделение авторских/итоговых значений, неизменность политики при переопределении, настоящие матрицы узлов при намеренно иных матрицах ragdoll, отсутствующие/некорректные узлы, однократное применение равномерного масштаба, геометрию доступа/осей, кадрирование слотов, публичную схему/структуру пакета, строгий JSON/защиту файлов и воспроизведение рецепта через CLI. Проверки сеанса охватывают точное открытие снимка, явные переопределения, совпавшие с изменёнными авторскими значениями, копии при чтении, выбор/режим, отклонение некорректного пакета действий и ограничение их числа. При наличии Node исполняется настоящий браузерный фасад и сравниваются его итоговое состояние, предпросмотр, меши, кадрирование и байты пакета с Python-фасадом; также проверяются настоящие методы панели для загрузки/скачивания рецепта с незавершённым провайдером и отклоняемыми импортами. Node — необязательный инструмент теста, а не зависимость продукта; остальные проверки используют только синтетические модели и матрицы в памяти.

## Проверки дополнений

Эти наборы проверяют API v1 и добавочные возможности обновления/данных сеанса в ветке
разработки; в существующем архиве 0.8.0 их нет.

`test_addons.py` проверяет неизменяемую установку ZIP, строгие манифесты и пути, лимиты
архива, сохранение включения, опасные установленные файлы, откат и настоящую межпроцессную
блокировку записи. Один случай установленной символьной ссылки пропускается, если Windows
запрещает её создание; отбраковка ссылок внутри ZIP выполняется. `test_addon_integration.py`
проверяет фасад, CLI, бинарную загрузку HTTP, защиту источника/iframe, выдачу включённых
ресурсов, согласованность Python и настоящего JS для сцены/морфов/камеры, копии данных,
атомарный отказ, проверку отправителя/API, отключённые фреймы и отложенный переход
из устаревшего фрейма.

`test_addon_update.py` проверяет явную замену отключённых пакетов с тем же ID, непрозрачные
метки версий, отказ повторной установки, отсутствующие/включённые цели, исправление отключённых
повреждённых пакетов, откат неверной замены, ошибки извлечения/публикации/замены состояния,
полные снимки читателей вокруг атомарной фиксации и настоящее завершение подпроцесса до неё.
Проверяются сохранение прежних байтов/невыбранных поколений, переход с v1 без отката к старым
байтам, привязка манифеста/поколения, фасад/взаимоисключающие флаги CLI, ограниченное обновление
байтами ZIP по HTTP с защитой источника, маршруты текущих и устаревших ресурсов поколений.
Файлы пакета и состояние сбрасываются перед фиксацией; проверки аварии процесса не доказывают
сохранность при любом отключении питания. Конкуренцию за блокировку записи проверяет
`test_addons.py`.

`test_addon_state.py` проверяет независимые конечные ациклические данные JSON, лимиты
байтов/глубины, согласованность байтового предела точного текста JSON при разном форматировании
кодировщиков и недопустимые данные; настоящий JS хоста/фасада с имитацией `sessionStorage`
проверяет изоляцию по ID, отказ подмены пространства имён, сохранение при пересоздании хоста,
повреждённый JSON, недоступность/превышение квоты, сохранение прежнего значения при отклонённой
записи и сброс данных без изменений морфов. Новое поколение не разрешает старому фрейму
изменять сцену или выполнять отложенный переход к модели. Node необязателен; эти проверки
не подтверждают правила восстановления сеанса конкретным браузером, долговременное хранение
проекта или визуальное качество интерфейса. Игра и установленные моды не используются.

`test_addon_exports.py` проверяет подготовку неизменяемых JSON/XML, ограничения UTF-8/имён/форматов, загрузку по действию пользователя в главном окне, повторную авторизацию, смену поколения/кадра/снимка, отмену и освобождение URL. `test_addon_wasm.py` проверяет разрешение только Wasm в CSP, адреса поколений и отказ сырым модулям; применение политики отдельно проверяется в браузере.
